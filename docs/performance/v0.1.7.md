# MarkMaid v0.1.7 performance baseline

Recorded on 2026-08-11 before performance optimization work. These numbers
characterize current pure frontend behavior; they are not CI pass/fail budgets.

## Commands

```sh
pnpm perf:fixtures
CI=true pnpm perf:smoke
pnpm perf:baseline
```

- `perf:fixtures` replaces `.perf-fixtures/v0.1.7/` with the deterministic
  generated tree and manifest.
- `perf:smoke` regenerates the tree and verifies its committed fingerprint,
  byte/count/depth/entry caps, production Quick Open result bounds, and
  production task-generation cancellation behavior. It contains no wall-clock
  assertion.
- `perf:baseline` regenerates the fixtures and writes local privacy-safe JSON
  reports to `artifacts/performance/v0.1.7-frontend.json` and
  `artifacts/performance/v0.1.7-native.json`. Native measurements run the real
  Rust render/index paths in a release build.

Both generated directories are ignored by Git. No fixture, timing code,
measurement history, telemetry endpoint, or upload path is imported by the
production application.

## Fixture definition

The committed definition is `performance/fixtures/manifest.json`. Generation
uses the fixed seed `markmaid-v0.1.7-fixed-seed-1`; the expected scenario
fingerprint is:

```text
c5e17371fed937f555509060d283d72b90edbb5f08ce5befc38e7f1b17932e97
```

The generated set contains:

- one exactly 8 MiB Markdown document containing headings, prose, tables,
  tasks, code, math, links, local images, and eight Mermaid fences;
- 3,072 representative workspace Markdown files, 48 hidden Markdown files,
  128 unsupported/noise files, duplicate names, and one symlink;
- separate depth-cap and 10,001-entry-cap workspace roots;
- mixed frontend tab batches of 10, 50, 100, and 200 records;
- Mermaid batches of 1, 10, and 50 diagrams with light/dark theme inputs; and
- deterministic synthetic command catalogs of 50, 250, and 500 entries.

Regeneration is idempotent: identical source definitions produce identical
scenario hashes, file byte counts, and tree shape. The generated manifest has
no timestamp or machine-specific path.

## Baseline environment and method

| Field | Value |
| --- | --- |
| Hardware | Apple M3 Pro, 12 logical CPUs, 18 GiB memory |
| Operating system | macOS 26.6.1, arm64 |
| Node.js | v26.7.0 |
| Fixture manifest | `c5e17371fed937f555509060d283d72b90edbb5f08ce5befc38e7f1b17932e97` |
| Profile | Frontend pure logic loaded through Vite SSR |
| Warm-up | One invocation per operation |
| Measurement | Nine samples; fast operations repeat within each sample for about 20 ms |

Fixture generation starts by replacing the generated tree and is therefore
cold filesystem setup. Frontend operation measurements then use parsed,
warmed, in-process fixture data. Native measurements run after a strict
preflight validates a ready 8 MiB Markdown render, an untruncated 3,072-entry
workspace index, and 50 successful Mermaid SVG renders; measured iterations
therefore use warmed process and filesystem caches. Both reports carry the
same run ID so cross-run artifacts are detectable. Median and p95 are computed
from the nine per-operation samples. Run the command with other foreground
workloads closed when capturing a release comparison.

## Captured frontend baseline

| Operation | Median | p95 |
| --- | ---: | ---: |
| Filter a synthetic 500-command catalog | 0.694 ms | 0.791 ms |
| Derive labels for 200 mixed tabs | 0.173 ms | 0.184 ms |
| Filter 3,072 workspace entries with 200 open tabs | 0.729 ms | 0.761 ms |
| Search the 8 MiB Markdown source | 3.406 ms | 3.571 ms |

The synthetic command-catalog p95 is below the product target of one 16 ms
animation frame on this machine. This is a baseline observation, not yet a
regression budget.

## Captured native release baseline

## Budgets and native coverage

Reviewed regression budgets are intentionally unset. Set them only after a
second clean capture confirms variance; use the larger of a justified absolute
floor or the accepted baseline plus documented tolerance. Wall-clock results
must remain outside normal CI.

The native report records release-mode median and p95 for the real 8 MiB
Markdown loader/renderer, the representative 3,072-file workspace index, and a
50-diagram Mermaid batch. It also records the CPU model, logical CPU count,
memory, operating system, architecture, build profile, and warmed-cache state.
Its benchmark entry point is ignored by normal Rust tests and runs only through
`perf:baseline`; ordinary CI keeps structural and cancellation assertions
without wall-clock thresholds.

## Privacy and production boundary

The committed document records only public fixture identifiers and aggregate
environment/timing values. Baseline JSON must not contain document contents,
user filenames, workspace paths, queries, usernames, installed-app inventory,
or raw errors. The runner loads only generated data, writes only locally, and
has no network or upload behavior.
