# MarkMaid v0.1.7 plan and implementation review

Reviewed 2026-08-11 against `v0.1.6..6306c37`
(`feat: implement v0.1.7 workflow improvements`) and
[`docs/plans/v0.1.7_plan.md`](plans/v0.1.7_plan.md).

## Summary

The implementation is broadly aligned with the planned
command-and-reading-workflow scope. The command registry is static and typed,
Focus Mode is runtime-only and DOM-preserving, external target IDs are
allowlisted and re-resolved natively, Copy Details stays on a privacy allowlist,
and performance tooling stays out of the production bundle.

`CI=true pnpm check` passes. Release publication is still blocked by unchecked
manual QA and artifact gates in
[`docs/releases/v0.1.7-checklist.md`](releases/v0.1.7-checklist.md).

The eight code findings below were resolved in the follow-up implementation.
Terminal behavior on the release machine remains a manual QA gate; artifact
creation and publication remain intentionally pending.

## Post-review release adjustment

Before artifact creation, the optional top tab-strip layout was retired. Open
tabs now use the single resizable left rail; Settings and Command Palette no
longer expose placement commands, diagnostics and current session snapshots no
longer contain `tabPlacement`, and older session-v1 snapshots safely ignore the
legacy field. Tab reordering language and keyboard behavior are vertical.

## Resolved findings

The original evidence below is retained as the pre-fix record; each resolution
note describes the current contract.

### Resolved P1 — Remove Root confirmation

**Resolution:** Every entry now uses the locked confirmation copy. Confirm
revalidates root membership, keeps disk files and open tabs, and focuses the
adjacent root or Add Folder; Cancel restores the original root.

The plan requires every **Remove Root** action to confirm that it only
unregisters workspace metadata and does not delete files. The actionable-state
button directly calls `runWorkspaceAction("unregister", ...)` in
[`src/main.ts`](../src/main.ts) (~L2831), and the unregister branch immediately
invokes `unregister_workspace_root` (~L3393). The tab context-menu
“Remove from Workspace” path uses the same unconfirmed action (~L3284).

The operation does not delete files, but one click still changes persisted
workspace state and can remove a pinned root without an explanatory gate. Route
this action through a confirmation dialog with copy such as “Remove from
Workspace? Files will remain on disk.” Then test cancel and confirm paths,
including preservation of open tabs.

### Resolved P1 — External discovery feedback and timeout

**Resolution:** Fast requests do not flash a loading message, feedback appears
at 100 ms, and a 5-second deadline produces recoverable
`discovery_timeout`. Generation-safe fake-timer tests cover retry, late results,
path changes, and replacement requests.

The plan requires discovery to show loading after 100 ms and either finish or
expose Retry by a bounded timeout. `ExternalAppController.load()` sets
`loading = true` immediately and awaits `listTargets()` with no timer, timeout,
cancellation handle, or timeout failure transition
([`src/app/external-app-controller.ts`](../src/app/external-app-controller.ts)
~L63). The menu can remain at “Finding applications…” forever if the native
Launch Services call stalls.

Add a bounded discovery deadline and a generation-safe timeout result. Keep late
results ignored, clear `loading`, and show a recoverable actionable error with
Refresh/Retry. Add fake-timer tests for the 100 ms feedback threshold, timeout,
retry, and a late native response.

### Resolved in code / manual QA pending P2 — Terminal capability proof

**Resolution:** An allowlisted terminal is shown only when installed and when
Launch Services reports it as a containing-directory URL handler; capability is
rechecked immediately before launch. Actual directory behavior remains a
release-machine QA gate, and a failing adapter must be hidden for v0.1.7.

The plan risk register calls for per-app terminal adapters and capability tests,
hiding unsupported destinations. The implementation only checks whether the
bundle exists, then opens the containing-directory URL through the same
`openURLs_withAppBundleIdentifier` helper for Terminal, iTerm2, Ghostty, and Warp
([`src-tauri/src/external_apps.rs`](../src-tauri/src/external_apps.rs) ~L440 and
~L552). Labels promise “Open containing folder in …”, but there is no adapter
test that the destination actually opens that folder as a working directory.

Verify each supported terminal’s directory-open behavior on the release machine.
If a destination only launches the app without opening the folder, either add a
safe native adapter for that app or omit it from v0.1.7 rather than advertising
folder open.

### Resolved P2 — Quick Open partial-results acknowledgement

**Resolution:** `continue-partial-results` is now the first action. It preserves
rows and acknowledges only the current query/index generation; query edits,
refresh, and reopen reset it.

The state matrix requires **Continue with Partial Results**, Refresh, and Copy
Details for a truncated Quick Open index. The implementation only emits Refresh
and Copy Details
([`src/actionable-state.ts`](../src/actionable-state.ts) ~L130); the matching
test locks that reduced behavior in
([`src/actionable-state.test.ts`](../src/actionable-state.test.ts)). Existing
rows remain usable, but the UI gives no explicit way to acknowledge that the
shown partial set is intentional.

Either add a `continue-partial-results` action that dismisses the truncation
notice while preserving results, or amend the plan and release copy to say that
selecting any visible result is the continuation path.

### Resolved P2 — Reveal availability probe

**Resolution:** Workspace and preview recovery show Reveal only after the
privacy-safe native probe succeeds. Activation probes again; a changed or
unsupported target removes the action and shows safe copy without a path or raw
native error.

For a failed workspace listing, `renderWorkspaceChildren()` unconditionally
passes `canReveal: true` ([`src/main.ts`](../src/main.ts) ~L2642). For preview
errors, `canReveal` is based only on the presence of an old
requested/canonical path string (~L4649). Neither confirms the path still
resolves before rendering Reveal.

This contradicts the plan’s “only valid recovery actions” rule and its explicit
“Reveal only when the path still resolves” condition for unavailable roots. A
missing root/file presents a button that predictably fails and creates a second
error. Carry a typed availability result from the native failure, or revalidate
before rendering/activating Reveal; cover missing and permission-denied paths
separately.

### Resolved with documented boundary P2 — External identity revalidation

**Resolution:** External opening records canonical path and file identity, then
repeats no-follow metadata, path, type, and identity validation immediately
before `NSWorkspace`. Replacement races are covered; the final pathname API is
explicitly not claimed as descriptor-level binding.

External handoff rejects a path when the initial `symlink_metadata` sees a
symlink, then canonicalizes it
([`src-tauri/src/external_apps.rs`](../src-tauri/src/external_apps.rs) ~L201).
If a regular file is replaced with a symlink between those calls, `canonicalize`
follows the symlink and the external target is opened for the resolved file.
Tests only cover a symlink that exists before validation (~L639), while the plan
asks for changed-path boundary tests.

At minimum, re-check the resolved object immediately before launch and add a
deterministic replacement-race test seam. If rejecting symlinks is a strict
security boundary rather than best effort, bind the selected file through a
no-follow identity strategy instead of relying on a pathname that can be
replaced.

### Resolved P3 — Viewer and Palette exclusivity

**Resolution:** Palette opening dismisses Mermaid/image viewers first, restores
the viewer opener, and then captures Palette focus. Escape closes only the
topmost overlay.

Opening the palette dismisses Quick Open, Find, export, external chooser, and
workspace dialogs
([`src/main.ts`](../src/main.ts) ~L600). An open Mermaid/image viewer from
[`src/diagram-viewer.ts`](../src/diagram-viewer.ts) is left in place. Escape is
then consumed by the palette while the viewer remains underneath.

Include the media viewer in palette exclusivity, or document viewers as
non-replaceable overlays and keep Escape priority explicit in tests.

### Resolved P3 — Contextual Focus Mode Exit control

**Resolution:** The control keeps layout and its accessible name while visually
hidden by default. Pointer presence in the titlebar or keyboard focus reveals
it, with reduced-motion and 200% zoom retained in QA.

The plan asks for a small Exit control that appears on keyboard focus or pointer
movement near the titlebar. The implementation keeps “Exit Focus Mode”
persistently visible in the titlebar while Focus Mode is active
([`src/main.ts`](../src/main.ts) ~L1694,
[`src/styles.css`](../src/styles.css) ~L462). This is more discoverable than the
planned hover/focus reveal, but it is a deliberate UX deviation and should be
accepted in the plan or adjusted before release copy freezes the behavior.

## What matches the plan well

- Static command catalog with stable IDs, availability revalidation before
  execute, result cap 50, IME-aware keys, and `⌘P` / `⇧⌘P` separation.
- Focus Mode omitted from session serialization; shell chrome hidden with
  `display: none` plus `inert`/`aria-hidden`, not opacity alone.
- External targets use opaque IDs, native re-resolution for applications, no
  shell plugin, bounded icon PNG bytes/cache, and no silent preferred-app
  fallback.
- Actionable-state model covers empty, workspace, preview, Quick Open failure,
  export, and external-open areas with allowlisted Copy Details.
- Performance fixtures, smoke gate, and local baseline docs exist without
  telemetry or wall-clock CI thresholds.
- Session remains v1 with optional `externalOpenTargetId`; invalid values are
  discarded.

## Release blockers and plan status (not code defects)

- Version metadata is synchronized at `0.1.7` across npm, Tauri, Cargo manifest,
  and Cargo lock metadata. Artifact creation and tagging remain separate gates.
- Manual QA remains open: keyboard/VoiceOver, 200% zoom,
  reduced-motion/transparency, real external-app disappearance, terminal
  destinations, and v0.1.6 regression paths.
- Performance budgets remain intentionally unset pending a second clean baseline
  capture.
- [`docs/releases/v0.1.7.md`](releases/v0.1.7.md) already links to a `v0.1.7`
  tag. Treat that document as publication-ready copy, not evidence that the tag
  exists yet.
- Roadmap correctly marks implementation complete with QA pending.

## Plan clarifications applied with the fixes

1. Remove Root confirmation is mandatory, with exact copy and deterministic
   root/Add Folder focus targets.
2. Discovery feedback is delayed 100 ms, times out at 5 seconds, and discards
   all late results from superseded generations.
3. Truncation recovery uses explicit per-query/index acknowledgement while
   preserving visible rows.
4. Reveal availability means a successful native no-follow probe of a regular
   file or directory, repeated again at activation.
5. Symlink defense is launch-time canonical-path and identity revalidation,
   explicitly not descriptor-level binding through `NSWorkspace`.
6. Terminal acceptance requires installed + Launch Services capability in code
   and actual containing-directory behavior on the release machine.
7. Media/diagram viewers are replaceable overlays and close before Palette
   focus capture.
8. Focus Mode Exit uses contextual pointer/focus reveal while remaining in the
   layout and accessibility tree.

## Fix order used

1. Discovery timeout + Retry (reliability).
2. Remove Root confirmation (safety contract).
3. Terminal destination verification or omission (user-facing correctness).
4. Reveal availability / symlink race hardening.
5. Truncation action or plan amendment.
6. Overlay exclusivity and Focus Mode Exit plan alignment.
7. Version bump, manual QA, second baseline, then release gates.
