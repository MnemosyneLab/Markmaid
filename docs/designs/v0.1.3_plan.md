# MarkMaid 工作区侧栏与状态栏：详细实施规格

## 1. 目标与边界

把 MarkMaid 从“只能单独打开 Markdown 的阅读器”扩展为“预览优先的本地文档工作区”：

- 用户可以固定多个常用目录，例如 `/Users/waltwang/Developer/fl/lua-odyssey/doc`。
- 左侧栏在 `Files` 与 `Open Tabs` 两个视图之间切换；两者复用同一宽度、显示状态和隐藏按钮。
- `Files` 是按需加载的目录树，只显示目录与支持预览的文件。
- 支持文件管理，但只作用于用户已固定的目录内：新建空 Markdown、创建文件夹、重命名、移到 macOS 废纸篓、在 Finder 中显示。
- 不新增 Markdown 编辑器；新建的空文档由用户在 Finder 或外部编辑器中编写。
- 底部状态栏始终显示，提供当前预览的必要状态、统计和主题信息。
- 不引入持续目录监听；应用自身操作后立即刷新树，外部变动仍由用户点击刷新或沿用现有激活/聚焦时的文档检查机制发现。

## 2. UI 与交互

### 左侧栏

将现有 `leftSidebarVisible` 从“仅左侧标签页模式”改为独立的工作区侧栏开关。默认状态：

- `Files` 为默认视图。
- 左侧栏默认显示。
- 现有 `top / left` 标签页偏好继续保留：
  - `top`：顶部仍展示横向标签栏；左侧栏可在 Files 与 Open Tabs 间切换。
  - `left`：顶部不展示标签栏；左侧栏切换到 Open Tabs 时展示现有纵向标签列表。
- 侧栏拖拽宽度继续使用现有 160–420px 限制。

`Files` 视图布局：

- 标题为 `Workspace`。
- 标题栏右侧有“添加固定目录”按钮；使用 macOS 原生目录选择器。
- 无固定目录时，显示空状态与 `Add Folder` 按钮。
- 每个固定根目录显示：
  - 根目录名称；
  - 完整路径作为悬浮提示；
  - 展开/收起箭头；
  - 右键菜单：刷新、在 Finder 中显示、从工作区移除。
- 根目录按固定顺序显示；第一版不支持拖拽排序。
- 目录和文件按“目录在前、文件在后、名称不区分大小写排序”显示。
- 所有树节点支持鼠标点击、双击、右键，以及键盘焦点、方向键展开/收起、Enter 打开、`Shift+F10` 或键盘菜单键打开菜单。

过滤规则：

- Markdown：`.md`、`.markdown`、`.mdown`、`.mkd`
- Mermaid：`.mmd`
- 图片：`.png`、`.jpg`、`.jpeg`、`.gif`、`.webp`、`.svg`、`.avif`、`.heic`、`.heif`、`.bmp`、`.tif`、`.tiff`
- 显示普通目录，以便用户继续进入子级或在其中创建内容。
- 隐藏点开头的文件/目录、符号链接，以及所有不在上述扩展名集合内的普通文件。
- 空目录仍显示；展开后显示“没有可显示的内容”，并仍可通过右键创建文档或文件夹。

双击行为：

- Markdown：复用现有 Markdown 加载与标签页预览。
- `.mmd`：打开一个 Mermaid 预览标签，使用现有 Rust/Merman 渲染链和现有缩放、拖拽、全屏查看、导出 SVG 能力。
- 图片：打开一个图片预览标签，使用应用内等比缩放预览；图片加载失败时显示文件信息与不可预览错误，不调用外部应用。
- 文件单击仅选中树节点；不改变当前预览，避免浏览目录时频繁切换内容。

### 右键菜单与文件操作

根目录不能被重命名或删除；“移除”仅取消固定，不影响磁盘内容。

目录菜单：

- 新建 Markdown 文件
- 新建文件夹
- 重命名
- 移到废纸篓
- 在 Finder 中显示
- 刷新当前目录

文件菜单：

- 打开预览
- 重命名
- 移到废纸篓
- 在 Finder 中显示

新建和重命名使用应用内轻量对话框，不依赖浏览器 `prompt`：

- 新建 Markdown：输入名称；无扩展名时自动追加 `.md`。
- 新建文件夹：输入目录名称。
- 名称不能为空，不能为 `.` 或 `..`，不能包含 `/`、`\` 或路径分隔符。
- 文件重命名必须保持为受支持的同类文件：Markdown 仍为 Markdown 扩展名、Mermaid 保持 `.mmd`、图片保持允许的图片扩展名。
- 同目录目标已存在时拒绝操作并显示“名称已存在”，不覆盖任何文件。
- 创建成功后展开父目录、刷新该分支并选中新节点；不自动打开空 Markdown 预览。
- 删除使用明确确认框：
  - 文件：`Move “name” to Trash?`
  - 非空目录：明确提示“该文件夹及其内容将移到废纸篓”。
- 删除成功后不保留失效预览：受影响文件或子目录中的已打开标签立即关闭，最近文档列表同步移除。

### 底部状态栏

状态栏横跨整个窗口底部，高度固定约 24px，不与文档滚动区域一起滚动。布局使用现有主题变量，窄窗口优先保留左侧信息，右侧低优先级内容自动隐藏或截断。

Markdown 状态：

- 左侧：`Markdown Preview · 128 lines · 2,041 words · 8,654 characters`
- 右侧：`12.4 KB · Modified 4 Aug 2026, 14:32 · Nord · Dark`

统计规则：

- 行数：按源文件物理换行计算。
- 字符数：按 Unicode code point 计算，不把 emoji 或中文拆成错误的 UTF-16 数量。
- 字数：优先使用 `Intl.Segmenter` 的 `word` 粒度并仅统计 `isWordLike` 项；平台不支持时回退到非空白片段计数。
- 文件大小使用 1024 进位的 `B / KB / MB / GB`。
- 修改时间使用本地时区格式化。
- 主题显示为当前颜色主题与已解析外观，例如 `System · Dark`、`Solarized · Light`。

其他状态：

- Mermaid：类型、行数、字符数、大小、修改时间、主题。
- 图片：`Image Preview`、文件大小、修改时间、主题；图片完成加载后追加像素尺寸。
- 加载中：文件名与 `Loading preview…`。
- 错误：错误状态与简短错误码。
- 空白工作区：`No preview open` 与当前主题。

## 3. 前端状态、类型与模块划分

在 `src/types.ts` 中扩展为通用预览标签，而不是把 Mermaid/图片伪装成 Markdown：

```ts
type SidebarView = "files" | "tabs";

type WorkspaceRoot = {
  id: string;
  canonicalPath: string;
  displayName: string;
};

type WorkspaceEntryKind = "directory" | "markdown" | "mermaid" | "image";

type WorkspaceEntry = {
  rootId: string;
  relativePath: string;
  canonicalPath: string;
  name: string;
  kind: WorkspaceEntryKind;
  sizeBytes?: number;
  modifiedAtMs?: number;
  hasVisibleChildren?: boolean;
};

type MermaidTab = {
  kind: "mermaid";
  key: `mermaid:${string}`;
  canonicalPath: string;
  displayName: string;
  source: string;
  html: string;
  sizeBytes: number;
  modifiedAtMs: number;
};

type ImageTab = {
  kind: "image";
  key: `image:${string}`;
  canonicalPath: string;
  displayName: string;
  assetUrl: string;
  sizeBytes: number;
  modifiedAtMs: number;
  dimensions: { width: number; height: number } | null;
};
```

`AppTab` 扩展为 Markdown、Mermaid、图片、设置页的联合类型。现有 `DocumentTab` 保持 Markdown 专用，避免破坏现有加载、刷新、目录大纲和文内搜索逻辑。

在 `AppState` 和持久化会话中新增：

```ts
sidebarView: SidebarView;
workspaceRoots: WorkspaceRoot[];
expandedWorkspacePaths: Record<string, string[]>;
```

兼容策略：

- 保持现有会话版本可读取。
- 缺失字段时回退为：
  - `sidebarView: "files"`
  - `workspaceRoots: []`
  - `expandedWorkspacePaths: {}`
- 原有标签、滚动位置、主题、最近文档和标签位置不改变。

新增纯前端模块，避免把目录树、统计与 `main.ts` 的 DOM 绑定混在一起：

- `src/workspace.ts`：树节点缓存、展开状态、路径前缀匹配、文件操作后的树与标签同步。
- `src/status.ts`：状态栏格式化、统计、文件大小和本地时间格式化。
- `src/workspace.test.ts` 与 `src/status.test.ts`：覆盖不依赖 DOM 的逻辑。
- `src/main.ts`：保留渲染、事件绑定和 Tauri invoke 编排。

标签同步规则：

- 文件重命名：保留该文件的预览内容与滚动位置，仅更新标签 key、路径、文件名和最近文档路径。
- 文件夹重命名：对该路径前缀下的 Markdown、Mermaid、图片标签和最近文档进行批量路径重写。
- 移到废纸篓：关闭精确匹配文件或位于被删除目录下的所有标签；若当前标签被关闭，沿用现有“选择相邻标签”的策略。
- Mermaid 主题或颜色主题改变时，现有 Markdown 中 Mermaid 和独立 `.mmd` 标签都重新走当前原生渲染链。

## 4. Rust 后端与文件系统边界

新增 `src-tauri/src/workspace.rs`，负责目录树、受控写入、Mermaid 文件预览和图片预览元数据；`src-tauri/src/lib.rs` 注册命令并维护根目录注册表。

命令接口：

```rust
register_workspace_root(path) -> WorkspaceRoot
unregister_workspace_root(root_id) -> ()
list_workspace_children(root_id, relative_path) -> Vec<WorkspaceEntry>
create_workspace_item(root_id, parent_relative_path, item_kind, name) -> WorkspaceEntry
rename_workspace_item(root_id, relative_path, new_name) -> WorkspaceMutation
trash_workspace_item(root_id, relative_path) -> WorkspaceMutation
load_workspace_mermaid(root_id, relative_path, mermaid_theme, color_theme) -> MermaidPreview
load_workspace_image(root_id, relative_path) -> ImagePreview
```

`WorkspaceMutation` 返回旧路径、新路径和受影响目录路径，供前端准确刷新和重写标签；删除返回被移除的路径前缀。

路径安全规则必须由 Rust 执行，不能只依赖前端：

- 固定目录时先 `canonicalize`，只接受可访问的真实目录；用后端生成的 `rootId` 保存其规范化路径。
- 后续列表和文件操作只接收 `rootId + relativePath`，不接收前端提供的任意绝对目标路径。
- `relativePath` 仅允许普通路径分量；拒绝绝对路径、`..`、平台前缀与空文件名。
- 访问已有项时，规范化后的目标必须仍在已注册根目录内。
- 创建和重命名目标时，先规范化父目录并检查其仍在根目录内，再以单个合法文件名拼接目标。
- 使用 `symlink_metadata` 识别并跳过符号链接；目录扫描、预览、重命名和删除都不跟随符号链接。
- 不允许对固定根目录本身执行重命名或移到废纸篓。
- 写入使用 `create_new`，禁止覆盖。
- 移到废纸篓通过 Rust 的 macOS Trash 实现，不使用 `remove_file` 或 `remove_dir_all`；为此加入专用废纸篓依赖，并将其封装在工作区模块内，避免业务代码直接触及删除实现。
- 错误返回稳定代码，例如 `outside_root`、`invalid_name`、`already_exists`、`not_found`、`permission_denied`、`unsupported_type`；前端映射为用户可读提示，不展示 Rust 调试文本。

预览实现：

- Markdown 树节点继续调用既有 `load_documents`，不改变现有 Markdown 安全渲染。
- `.mmd` 读取 UTF-8 源文本后复用 `document.rs` 中当前的 `HeadlessRenderer`/Merman 逻辑，返回与 Markdown Mermaid figure 相同的安全 HTML；渲染失败时仍返回可打开的预览页，显示错误和安全转义后的源代码。
- 图片只在后端确认扩展名、常规文件、根目录归属并授权 Tauri asset protocol 后返回规范化路径；前端通过 `convertFileSrc` 放入 `<img>`，绝不将 SVG 或图片内容以内联 HTML 注入。
- 现有 Markdown 文档中的图片授权、危险链接拦截和 Mermaid SVG 安全处理保持不变。

## 5. 实施顺序

1. 在 `types.ts`、`state.ts` 中加入侧栏/工作区持久化字段和通用预览标签基础，先完成旧会话兼容测试。
2. 新建 `workspace.rs`：实现根目录注册、路径验证、浅层目录枚举、过滤、创建、重命名和废纸篓移动；在 `lib.rs` 注册命令。
3. 为 `.mmd` 抽出可复用的原生渲染入口，并实现图片预览元数据与 asset scope 授权。
4. 新增 `workspace.ts` 与 `status.ts` 纯逻辑模块及单元测试。
5. 改造 `main.ts`：渲染 Files/Open Tabs、懒加载树、上下文菜单、名称与删除确认对话框、预览标签和状态栏。
6. 扩展主题切换、关闭标签、快速切换、最近文档、标题和刷新逻辑，使其安全处理三种预览类型。
7. 补齐样式、键盘可访问性、窄窗口截断和空/错误状态。
8. 更新 README 的产品定位、支持的工作区文件类型、文件操作范围和“无内置编辑器/无持续监听”说明。

## 6. 测试与验收

前端单元测试：

- 新旧会话均可恢复；新增字段缺失时使用默认值。
- 根目录去重、展开状态持久化、目录排序、路径前缀重写。
- 文件/目录删除关闭正确标签并清理最近文档。
- Markdown、Mermaid、图片、加载、错误、空白状态的状态栏内容。
- Unicode 字符数、中文/英文词数、文件大小、时间和主题格式化。
- 快速切换、标签标题和关闭逻辑不因 Mermaid/图片标签回归。

Rust 单元测试，使用临时目录：

- 支持/不支持扩展名、隐藏项和符号链接过滤。
- 根目录、嵌套目录、空目录和排序。
- 拒绝绝对路径、`..`、根目录逃逸、重名覆盖和非法名称。
- 创建空 Markdown、创建文件夹、同类扩展重命名。
- 文件及目录重命名的受影响路径结果。
- Mermaid `.mmd` 成功渲染、无效 Mermaid 的安全错误页、无效 UTF-8 错误。
- 图片类型验证与 asset scope 授权。
- 废纸篓逻辑通过适配层测试路径选择和错误映射；不在自动化测试中真实清空用户废纸篓。

手工验收：

- 固定两个目录、重启后仍存在，展开状态仍存在。
- 在深层目录创建、重命名、移到废纸篓后，树和打开标签立即一致。
- Markdown、`.mmd`、PNG/SVG 都能在应用内打开；Mermaid 仍可缩放和导出。
- `.git`、普通源码、二进制和符号链接不出现在树中。
- 深色/浅色与所有现有颜色主题中，状态栏、树选中态、菜单和确认框均可读。
- 标签位于顶部或左侧、侧栏隐藏/显示、窄窗口三种情况下布局正常。
- 运行 `pnpm check`，再完成 macOS Apple Silicon 调试打包验证。

## 7. 明确不做的事项

- 不做 Markdown 文本编辑、保存、自动创建内容模板或撤销/重做。
- 不做目录外的任意文件管理。
- 不做拖拽移动文件、复制/粘贴文件、批量操作、全文搜索或持续文件系统监控。
- 不改变现有 Markdown 的安全策略、Merman 原生渲染方案、macOS ARM 目标或现有文档打开方式。
