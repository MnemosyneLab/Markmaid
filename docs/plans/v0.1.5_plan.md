# MarkMaid v0.1.5 Plan

## Summary

MarkMaid 0.1.5 hardens the preview-first workspace after v0.1.4:

- Reliability for open / reload failures and unified Mermaid / image open paths
- Large-folder performance for the Files tree and Quick Open
- Tighter local image authorization and print-export cleanup
- Docs and navigation consistency (Copy-only code blocks; one Back / Forward model)

## Scope

### Reliability

- Surface open / reload failures as error tabs or status-bar notices instead of leaving
  placeholders stuck at `status: "loading"`.
- Unify drag-and-drop, second-instance / argv open, and Files-tree open so `.mmd` and
  images open the same way Markdown does; update drop overlay copy accordingly.
- Collapse dual navigation history (`tab.history` vs global `documentVisitHistory`) into
  one model used by menu shortcuts, UI, and tests.
- Correct README / CHANGELOG / examples that claim code-block Download; keep Copy only.

### Large-folder performance

- Skip known noise directories (at least `.git`, `node_modules`) in Files visibility walks
  and Quick Open indexing.
- Bound or cache `directory_contains_visible_item` so pinning large trees does not freeze
  the UI.
- Add depth and/or entry caps to `index_workspace_markdown`, keeping stale-response
  rejection.

### Security

- Authorize local Markdown images under the document directory and/or pinned workspace
  roots; revoke asset-protocol grants when tabs close.
- Add load timeout / cleanup for hidden print-export webviews; narrow their capabilities
  where practical.

### Maintainability (as needed for the above)

- Add orchestration tests for: open/reload error → error tabs; non-Markdown drop/open;
  Back/Forward against the single history model; print lifecycle timeout.
- Prefer extracting focused modules from `main.ts` only when it unblocks the work above;
  a full shell split is optional stretch, not a release blocker.

## Explicitly Out of Scope

- Markdown editing or saving
- Continuous filesystem watching
- Workspace full-text body search
- Code-block Download action
- Heavy PDF rendering dependencies; keep native print sheet
- Broad filesystem permissions
- Developer ID / notarized releases (optional follow-up)
- Pinned-folder drag reorder and file drag-move
- Persisting closed-tab or visit history across sessions
- “Open in External Editor” (candidate for a later release)

## Verification

- Frontend Vitest covers open/reload error surfaces, unified preview open kinds,
  single navigation history, and Find / docs regressions touched by this release.
- Rust tests cover workspace ignore / visibility bounds, Quick Open caps, and tightened
  image authorization / revoke behavior.
- `pnpm check` remains the complete quality gate: TypeScript, Vitest, Vite build, Rust
  tests, formatting, and Clippy.
- Manual QA: drop / second-instance open for `.md` / `.mmd` / images; pin a large folder
  with `node_modules`; Quick Open responsiveness; open → close Markdown with relative
  images; export PDF print window closes on success and failure paths; Back / Forward
  across links and tabs.

## Implementation Status

Planned. Version metadata is already at `0.1.5`; implementation and release notes are
not started. Prior research that seeded this plan lived in `docs/plans/next_priorities.md`
and is superseded by this document.

## Delivery order

1. Reliability — open/reload errors; unified Mermaid/image open; docs Download fix;
   single navigation history
2. Large-folder performance — ignores, visibility short-circuit/cache, Quick Open caps
3. Security — scoped asset authorization + revoke; print-window timeout/cleanup
4. Tests for the paths above; optional `main.ts` extractions only if needed
