# MarkMaid v0.1.5 Final Plan

## 1. Decision summary

v0.1.5 remains a hardening release for the preview-first, read-only workspace.
Its goal is to make opening, navigation, large pinned folders, local assets, and
native PDF printing predictable without expanding MarkMaid into an editor or a
continuous file watcher.

The original plan has the right product direction. DeepSeek's review is also
substantially correct: it correctly identified the non-revocable Tauri asset
scope, the already-covered `.git` case, the root-only Mermaid/image commands,
the Markdown loading rejection gaps, the unused per-tab history, and the print
window watchdog/capability gap.

This final plan makes three additional decisions:

1. Security is implemented before broadening the open-path surface. Local image
   paths are checked against an explicit policy before `allow_file` is called;
   directory-level grants and per-tab revocation are not introduced.
2. Files visibility scanning gets a blocking execution path and a bounded,
   conservative scan. Reaching the bound makes a directory visible rather than
   incorrectly hiding a directory that may contain a supported file.
3. “Unified open” is a single openable-path contract shared by the Open dialog,
   drag and drop, argv/second-instance, macOS `Opened`, Markdown links, and the
   Files tree. Quick Open remains Markdown-only by design.

## 2. Product boundary

### In scope

- Reliable error states for first open, lazy restore, and reload.
- Internal preview opening for Markdown, standalone Mermaid (`.mmd`), and
  supported image files.
- One global document visit history for Back / Forward, including relative
  Markdown links, same-document anchors, tab switches, and scroll positions.
- Large-folder protection for the Files tree and Quick Open indexing.
- Bounded local-image authorization and a documented session-lifetime grant
  model.
- Native print window load timeout, cleanup, and least-privilege capability
  separation.
- Documentation consistency and release verification for v0.1.5.

### Explicitly out of scope

- Markdown editing or saving.
- Continuous filesystem watching.
- Workspace full-text body search.
- Indexing Mermaid or image files in Quick Open.
- Code-block Download; code blocks remain Copy-only.
- Heavy PDF rendering dependencies; keep the native macOS print sheet.
- Broad filesystem permissions or a general-purpose local-file protocol.
- Per-tab revocation of Tauri asset grants in the current process.
- Persisting closed-tab or visit history across sessions.
- Pinned-folder drag reorder, file drag-move, or “Open in External Editor”.
- Developer ID/notarized release work.

## 3. Current-state assessment and review disposition

| Finding | Decision | Reason |
| --- | --- | --- |
| Tauri asset grants cannot be revoked in the current API | Adopt | Do not promise `revoke` behavior in v0.1.5. Keep grants per file and narrow the paths before granting. A custom protocol is a later security project. |
| `.git` is missing from the ignore work | Correct | Existing dotfile filtering already excludes `.git` in the tree, visibility walk, and Markdown index. Add regression coverage, but do not count `.git` as new behavior. |
| Non-dotfile noise needs an explicit policy | Adopt and clarify | Skip a fixed, case-insensitive set such as `node_modules`, `dist`, `build`, `.venv`, `Pods`, and `target` in both tree visibility and Quick Open indexing. These directories and their supported files are intentionally invisible in v0.1.5. |
| `directory_contains_visible_item` needs protection | Adopt and strengthen | It recursively scans synchronously. Move the command work to `spawn_blocking`, reuse a per-request memo, skip noise, and use a conservative scan budget. Budget exhaustion keeps the directory visible instead of producing a false empty result. |
| Quick Open needs concrete limits | Adopt | Use explicit depth and entry limits, preserve stale-response rejection, and return truncation metadata so the UI does not imply that a capped index is complete. |
| Mermaid/image open needs more than frontend routing | Adopt | Use one backend openable-path dispatcher or equivalent shared loader. It must validate and classify the absolute path, then return a per-path tagged result or error. Files-tree roots remain the authorization boundary for workspace mutations, not a requirement for explicitly opened previews. |
| Markdown open/reload can leave `loading` tabs stuck | Adopt | Catch command rejection in both batch open and lazy loading. A first-open failure becomes an error tab; a ready document that fails reload keeps its old preview and receives a reload notice. |
| Per-tab history is a second model | Adopt | Keep `documentVisitHistory` as the only Back / Forward source of truth. Remove the unused `history` / `historyIndex` fields and update state migration/tests. |
| Print export needs a Rust watchdog and narrower capability | Adopt | A page that never finishes loading cannot start the existing frontend timer. Add a Rust load/handshake timeout, make cleanup one-shot, and stop granting the print window dialog/store/opener/window-state permissions. |
| Directory-level asset authorization is the preferred fix | Modify | It is feasible, but broader than necessary. Prefer policy-checked per-file `allow_file`; use workspace roots to decide whether a Markdown asset is allowed, not to grant an entire directory blindly. |

## 4. Contracts to establish before implementation

### 4.1 Openable-path contract

Define one internal classification used by all internal preview entry points:

```text
markdown -> Markdown document tab
mermaid  -> standalone Mermaid preview tab
image    -> image preview tab
other    -> no preview; visible unsupported-file notice
```

The Rust side remains authoritative for regular-file checks, symlink rejection,
canonicalization, supported extensions, UTF-8 validation, Mermaid rendering, and
image authorization. The frontend may classify early to render the correct
loading placeholder, but must handle the backend result as authoritative.

The shared loader must:

- accept absolute paths for explicitly opened `.mmd` and image files, not only
  `rootId` plus `relativePath`;
- keep Markdown loading behavior and per-path error results;
- route Files-tree opens through the same loader as drag/drop and argv opens;
- preserve canonical-path tab deduplication;
- return enough information to map each result to its requested path and tab;
- reject directories, symlinks, unsupported extensions, unreadable files, and
  invalid Mermaid UTF-8 with an error result rather than silently dropping them.

`load_workspace_mermaid` and `load_workspace_image` may remain as compatibility
wrappers during the refactor, but there must be one tested implementation path.
Workspace mutation commands continue to require a registered root and remain
root-relative.

Unsupported dropped or opened paths do not create error tabs. They produce one
short status-bar/workspace notice summarizing ignored paths. Supported paths that
fail to load do create error tabs.

### 4.2 Local-image authorization policy

Keep `resolve_image` responsible for resolving and canonicalizing a local image,
but move the trust decision into a pure authorization helper before
`asset_protocol_scope().allow_file(path)` is called.

For a Markdown document, a canonical local image is authorized only when:

1. it is a regular supported image file; and
2. it is inside the document's containing directory subtree, or the document is
   inside a currently registered pinned workspace root and the image is inside
   that same root.

Therefore a Markdown file outside any pinned root can use assets beside it or
below it, while a Markdown file in a pinned root can use assets elsewhere in that
same pinned root. An absolute `file://` image outside the allowed boundary is
rendered as blocked and is never passed to `allow_file`.

The loader obtains the registered roots from trusted Rust state; the frontend
does not submit an arbitrary list of roots. Directly opened image tabs authorize
the validated, explicitly requested image file itself. All grants are accepted as
process-lifetime grants because the current Tauri API does not provide a safe
revocation operation. The plan must not claim that closing a tab revokes access.

### 4.3 Error-state contract

Add a small, testable frontend reducer/helper for command failures:

- first open or lazy restore rejection: replace the matching loading tab with an
  error tab;
- ready Markdown reload returning an error result or rejecting: retain the ready
  tab and set the existing reload-error/status notice;
- loading/error tab reload rejection: replace or update it as an error tab;
- stale completions after close, rename, retry, or a newer request: do not modify
  the newer tab state.

The helper must be used by batch Markdown open, lazy preview loading, direct
Mermaid/image loading, and reload. `finally` cleanup of pending request keys is
required on every path.

## 5. Implementation workstreams

### Workstream A — Safe unified preview opening

1. Extract the openable-path classification and result-to-tab mapping into a
   focused frontend module or reducer seam.
2. Add the shared Rust loader/dispatcher described above. Generalize standalone
   Mermaid and image loading to absolute validated paths, while keeping root
   checks for Files tree operations.
3. Replace the Markdown-only filtering in `openDocumentPaths` with one
   `openPreviewPaths` flow that creates the correct placeholder per path and
   applies results by requested-path identity.
4. Route all sources through it:
   - `⌘O` / Open dialog;
   - native drag and drop;
   - initial argv and single-instance forwarding;
   - macOS `RunEvent::Opened`;
   - relative links from Markdown;
   - Files-tree open actions.
5. Update the dialog title, toolbar/empty-state text, drop overlay, and notices
   to say Markdown, Mermaid, or image files where appropriate.
6. Keep Quick Open results Markdown-only and continue to exclude `.mmd` and
   images from its inventory.
7. Decide and test one behavior for unsupported paths: ignore the path with a
   visible notice, without launching an external application implicitly.

### Workstream B — Loading and reload reliability

1. Catch `invoke` rejection in batch open, `ensurePreviewLoaded`, and
   `reloadActiveDocument`.
2. Apply the error-state contract without reviving a tab that has been closed or
   replaced while the command was pending.
3. Preserve the existing ready-preview-on-reload-failure behavior, including the
   status-bar notice and retry path.
4. Add a reducer-level test matrix for first open, lazy restore, direct preview,
   ready reload failure, loading reload failure, retry, and stale completion.

### Workstream C — One navigation history

Use `documentVisitHistory` / `documentVisitHistoryIndex` as the only navigation
model. A visit entry remains `{ path, scrollTop, fragment? }` and is capped at
`MAX_DOCUMENT_NAVIGATION_HISTORY`.

- Remove `history` and `historyIndex` from ready document tabs and from the
  associated state helpers/tests.
- Update relative-link and same-document-anchor handling to record the global
  entry directly.
- Before changing tabs or navigating, capture the current scroll position into
  the current global entry.
- Back/Forward moves the global index, activates an existing ready tab or loads
  the target without recording a new visit, then restores scroll/anchor state.
- Preserve boundary no-ops and branch truncation after navigating from the
  middle of history.
- Continue to treat history as session-only; old persisted tabs may contain no
  history fields, so restore code must ignore legacy fields safely.

### Workstream D — Large-folder Files tree

Introduce shared constants and helpers in `workspace.rs`:

```text
NOISE_DIRECTORY_NAMES = node_modules, dist, build, .venv, Pods, target
MAX_VISIBILITY_SCAN_ENTRIES = 2,000
MAX_VISIBILITY_SCAN_DEPTH = 32
```

Names are compared case-insensitively. Existing hidden-entry and symlink rules
remain in force; `.git` is covered by regression tests rather than treated as a
new exception.

`directory_contains_visible_item` should return a three-state internal result:
fully scanned and visible, fully scanned and empty, or scan budget exhausted.
The last state is exposed as a visible directory so a bounded scan cannot hide a
potentially useful subtree. Reuse a per-request `HashMap<PathBuf, ...>` memo.

Run `list_workspace_children` on `spawn_blocking` using a root snapshot, rather
than holding registry state or blocking the Tauri command thread during a deep
walk. Existing frontend request invalidation/stale-response checks must remain
effective after the command becomes asynchronous. Mutation and refresh paths
must invalidate any relevant visibility result.

### Workstream E — Bounded Quick Open indexing

Keep Quick Open as filename/path-only Markdown search. Add these backend limits:

```text
MAX_INDEX_DEPTH = 12
MAX_INDEXED_MARKDOWN_ENTRIES_PER_ROOT = 10,000
```

The walk skips hidden entries, symlinks, and the same noise-directory set as the
Files tree. Child traversal and final sorting are deterministic and
case-insensitive. A root that reaches a depth or entry limit is not treated as
unavailable; return a new `truncatedRootIds` field in
`WorkspaceMarkdownIndex`.

The Quick Open UI keeps the existing 200-result display cap and stale request-id
rejection. If any root is truncated, show a short hint that the index is capped
and that a narrower query may reveal the desired result. If a root is unavailable,
retain the existing partial-results behavior.

### Workstream F — Print lifecycle and capability hardening

1. Add a Rust-side watchdog beginning when a print-export window is created. If
   the bundled `print.html` page does not reach the load/handshake point within a
   bounded interval (target: 30 seconds), close the window and report an error to
   the main window.
2. Make the watchdog race-safe with successful `afterprint`, explicit
   `finish_print_export`, page-evaluation failure, and window-close paths.
3. Keep the frontend asset wait, but replace the unlabelled ten-minute constant
   with named load and interaction timeouts. Use a shorter bounded interaction
   guard (target: five minutes), clear it on every finish/error path, and ensure
   only one finish call can close a window.
4. Split capabilities so `main` keeps the normal app permissions while
   `print-export-*` receives only the core window/webview permissions needed by
   the print flow. Do not inherit dialog, opener, store, or window-state
   permissions for print windows. Keep the existing Rust label-prefix validation.
5. Manually verify success, user cancellation, print-command failure, asset
   timeout, page-load timeout, and absence of orphaned hidden windows.

### Workstream G — Documentation and release consistency

Update all stale code-block Download claims to Copy-only, including:

- `README.md` feature and shortcut wording;
- the relevant historical `CHANGELOG.md` entry;
- `docs/examples/gfm-and-code.md` and any adjacent example instructions.

Also update user-facing Open text to reflect the unified Markdown/Mermaid/image
path where it is accurate. Keep Quick Open documentation explicit that its
inventory is Markdown-only. Update the changelog with the final v0.1.5 behavior,
including the intentional session-lifetime asset-grant limitation if it is
user-visible.

## 6. Tests and acceptance criteria

### Frontend tests

- openable-path classification and unsupported-path notice behavior;
- mapping Markdown, Mermaid, and image results to the correct tab kind;
- command rejection to error tab, including stale-request protection;
- ready reload failure retaining the prior preview;
- one global history model across relative links, anchors, tab switches,
  Back/Forward, scroll restoration, boundaries, and branch truncation;
- Quick Open truncated/unavailable-root messaging and existing 200-result cap.

### Rust tests

- case-insensitive `classify_file` and shared open dispatch;
- absolute Mermaid/image loading, invalid UTF-8, directories, symlinks, and
  unsupported extensions;
- image authorization for document-directory assets, same-pinned-root assets,
  out-of-bound `file://` paths, and documents outside pinned roots;
- explicit-image authorization for direct image tabs;
- hidden/dotfile and noise-directory skipping, including `.git` regression;
- visibility memo/budget behavior, including budget exhaustion remaining visible;
- Quick Open depth/entry caps, deterministic ordering, truncation metadata, and
  nested-root deduplication;
- print-window label/watchdog state helpers where the behavior can be tested
  without a GUI.

### Quality gates

- `CI=true pnpm check` must pass: TypeScript, Vitest, Vite build, Rust tests,
  formatting, and Clippy.
- Build the Apple-Silicon debug app before release sign-off:
  `CI=true pnpm tauri build --debug --bundles app --target aarch64-apple-darwin`.
- Confirm `git diff --check`, version metadata, changelog links, and release
  assets before tagging.

### Manual QA matrix

1. Open valid and invalid `.md`, `.mmd`, and image files through the dialog,
   drag/drop, Finder Opened, argv/second-instance, Markdown links, and Files.
2. Drop unsupported files and confirm a visible notice with no accidental
   external launch.
3. Exercise missing files, invalid UTF-8, permission/read failures, lazy restore,
   ready reload failure, retry, and close-while-loading.
4. Pin a fixture containing `node_modules`, `dist`, `target`, deep nesting, many
   unsupported files, and more than the Quick Open cap. Confirm responsiveness,
   truncation messaging, no false empty-directory hiding, and stale results are
   discarded after refresh/mutation.
5. Verify local images inside the allowed document/root boundary render, while
   out-of-bound `file://` images show the blocked fallback. Close the tab and
   confirm behavior is documented as session-lifetime authorization, not
   revocation.
6. Traverse Markdown links and anchors across tabs, then test Back/Forward,
   scroll restoration, tab close/reopen, and history boundaries.
7. Export HTML and PDF; verify print success, cancellation, failure, asset wait,
   page-load timeout, print-window cleanup, and capability restrictions.
8. Run a final search for stale “code-block Download” claims.

## 7. Delivery order

1. Establish the path-classification, image-authorization, error-state, and
   history tests/contracts.
2. Implement the safe shared loader and unified open flow, including error
   handling for all sources.
3. Collapse navigation state to the global visit history and update docs/UI copy.
4. Implement Files-tree noise filtering, bounded visibility, async execution,
   and Quick Open limits/truncation metadata.
5. Harden print lifecycle and capability separation.
6. Run the complete test/manual matrix, update changelog/release assets, and
   perform the arm64 build gate.

The release is complete only when the quality gate, arm64 build, manual matrix,
and documentation checks pass. No workstream should silently reintroduce
editing, file watching, broad filesystem grants, Quick Open body search, or
per-tab asset revocation.
