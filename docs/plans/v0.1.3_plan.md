# MarkMaid Workspace Sidebar and Status Bar: Detailed Implementation Spec

## 1. Goals and Boundaries

Extend MarkMaid from “open Markdown files one at a time” into a “preview-first local document workspace”:

- Users can pin multiple frequently used folders, for example `/Users/waltwang/Developer/fl/lua-odyssey/doc`.
- The left sidebar switches between `Files` and `Open Tabs`; both share the same width, visibility, and hide control.
- `Files` is a lazy-loaded directory tree showing only folders and previewable files.
- File management is allowed only inside pinned folders: create empty Markdown, create folders, rename, move to macOS Trash, Reveal in Finder.
- Do not add a Markdown editor; users write new empty documents in Finder or an external editor.
- The bottom status bar is always visible and shows essential preview status, stats, and theme info.
- Do not add continuous directory watching; refresh the tree immediately after in-app actions. External changes still rely on user refresh or the existing activation/focus document-check flow.

## 2. UI and Interaction

### Left sidebar

Change the existing `leftSidebarVisible` from “left tabs mode only” into an independent workspace sidebar toggle. Defaults:

- `Files` is the default view.
- The left sidebar is visible by default.
- Keep the existing `top / left` tab preference:
  - `top`: horizontal tab bar remains on top; the left sidebar can switch between Files and Open Tabs.
  - `left`: no top tab bar; when the sidebar is on Open Tabs it shows the existing vertical tab list.
- Sidebar drag width keeps the existing 160–420px limits.

`Files` view layout:

- Title is `Workspace`.
- Title bar has an “Add pinned folder” button on the right; use the native macOS folder picker.
- With no pinned folders, show an empty state and an `Add Folder` button.
- Each pinned root shows:
  - root display name;
  - full path as hover tooltip;
  - expand/collapse chevron;
  - context menu: Refresh, Reveal in Finder, Remove from Workspace.
- Roots appear in pin order; v1 does not support drag reorder.
- Directories and files sort as directories first, then files, case-insensitive by name.
- All tree nodes support click, double-click, context menu, keyboard focus, arrow expand/collapse, Enter to open, and `Shift+F10` or the keyboard menu key for menus.

Filter rules:

- Markdown: `.md`, `.markdown`, `.mdown`, `.mkd`
- Mermaid: `.mmd`
- Images: `.png`, `.jpg`, `.jpeg`, `.gif`, `.webp`, `.svg`, `.avif`, `.heic`, `.heif`, `.bmp`, `.tif`, `.tiff`
- Show ordinary directories so users can descend or create content inside them.
- Hide dotfiles/dirs, symlinks, and every plain file outside the extension set above.
- Empty directories still appear; when expanded they show “Nothing to show”, and users can still create documents or folders via the context menu.

Double-click behavior:

- Markdown: reuse existing Markdown load and tab preview.
- `.mmd`: open a Mermaid preview tab using the existing Rust/Merman render chain and existing zoom, pan, fullscreen, and export SVG.
- Images: open an image preview tab with in-app proportional zoom; on load failure show file info and a non-previewable error — do not launch an external app.
- Single-click only selects the tree node; do not change the current preview, so browsing the tree does not thrash content.

### Context menus and file operations

Roots cannot be renamed or deleted; “Remove” only unpins and does not affect disk contents.

Directory menu:

- New Markdown File
- New Folder
- Rename
- Move to Trash
- Reveal in Finder
- Refresh this directory

File menu:

- Open Preview
- Rename
- Move to Trash
- Reveal in Finder

Create and rename use a lightweight in-app dialog, not the browser `prompt`:

- New Markdown: enter a name; append `.md` when no extension is given.
- New Folder: enter a directory name.
- Names must be non-empty, not `.` or `..`, and must not contain `/`, `\`, or path separators.
- File renames must stay within the supported kind: Markdown keeps a Markdown extension, Mermaid stays `.mmd`, images keep an allowed image extension.
- If the target already exists in the same directory, reject with “Name already exists” and never overwrite.
- After a successful create, expand the parent, refresh that branch, and select the new node; do not auto-open an empty Markdown preview.
- Deletes use an explicit confirmation:
  - File: `Move “name” to Trash?`
  - Non-empty directory: clearly state that the folder and its contents will move to Trash.
- After a successful delete, do not keep stale previews: immediately close affected open tabs (exact file or anything under a deleted directory) and remove matching recents.

### Bottom status bar

The status bar spans the full window bottom at a fixed ~24px height and does not scroll with the document. Use existing theme variables; on narrow windows keep left-side info first and hide or truncate lower-priority right-side content.

Markdown status:

- Left: `Markdown Preview · 128 lines · 2,041 words · 8,654 characters`
- Right: `12.4 KB · Modified 4 Aug 2026, 14:32 · Nord · Dark`

Stats rules:

- Lines: physical newlines in the source file.
- Characters: Unicode code points — do not split emoji or CJK into incorrect UTF-16 counts.
- Words: prefer `Intl.Segmenter` with `word` granularity and count only `isWordLike` items; fall back to non-whitespace token counts when unsupported.
- File size uses 1024-based `B / KB / MB / GB`.
- Modified time uses local timezone formatting.
- Theme shows the current color theme and resolved appearance, e.g. `System · Dark`, `Solarized · Light`.

Other statuses:

- Mermaid: kind, lines, characters, size, modified time, theme.
- Image: `Image Preview`, file size, modified time, theme; append pixel dimensions after load.
- Loading: filename and `Loading preview…`.
- Error: error state and a short error code.
- Empty workspace: `No preview open` and the current theme.

## 3. Frontend State, Types, and Module Split

Extend `src/types.ts` for general preview tabs instead of disguising Mermaid/images as Markdown:

```ts
type SidebarView = "files" | "tabs";

type WorkspaceRoot = {
  id: string;
  canonicalPath: string;
  displayName: string;
};

type WorkspaceEntryKind = "directory" | "markdown" | "mermaid" | "image";

type WorkspaceEntry = {
  rootId: string;
  relativePath: string;
  canonicalPath: string;
  name: string;
  kind: WorkspaceEntryKind;
  sizeBytes?: number;
  modifiedAtMs?: number;
  hasVisibleChildren?: boolean;
};

type MermaidTab = {
  kind: "mermaid";
  key: `mermaid:${string}`;
  canonicalPath: string;
  displayName: string;
  source: string;
  html: string;
  sizeBytes: number;
  modifiedAtMs: number;
};

type ImageTab = {
  kind: "image";
  key: `image:${string}`;
  canonicalPath: string;
  displayName: string;
  assetUrl: string;
  sizeBytes: number;
  modifiedAtMs: number;
  dimensions: { width: number; height: number } | null;
};
```

`AppTab` becomes a union of Markdown, Mermaid, image, and settings. Keep `DocumentTab` Markdown-only so existing load, refresh, outline, and in-document Find logic stay intact.

Add to `AppState` and the persisted session:

```ts
sidebarView: SidebarView;
workspaceRoots: WorkspaceRoot[];
expandedWorkspacePaths: Record<string, string[]>;
```

Compatibility:

- Keep existing session versions readable.
- Missing fields fall back to:
  - `sidebarView: "files"`
  - `workspaceRoots: []`
  - `expandedWorkspacePaths: {}`
- Existing tabs, scroll positions, theme, recents, and tab placement stay unchanged.

Add pure frontend modules so tree/stats logic is not mixed with `main.ts` DOM binding:

- `src/workspace.ts`: tree cache, expand state, path-prefix matching, tree/tab sync after file ops.
- `src/status.ts`: status-bar formatting, stats, size, and local time.
- `src/workspace.test.ts` and `src/status.test.ts`: cover DOM-free logic.
- `src/main.ts`: keep render, event binding, and Tauri invoke orchestration.

Tab sync rules:

- File rename: keep that file’s preview content and scroll; only update tab key, path, filename, and recent path.
- Folder rename: bulk-rewrite Markdown, Mermaid, image tabs and recents under that path prefix.
- Move to Trash: close exact-match files or any tabs under the deleted directory; if the active tab closes, reuse the existing “select neighboring tab” strategy.
- When Mermaid or color theme changes, both Markdown-embedded Mermaid and standalone `.mmd` tabs re-run the current native render chain.

## 4. Rust Backend and Filesystem Boundaries

Add `src-tauri/src/workspace.rs` for the directory tree, controlled writes, Mermaid file preview, and image preview metadata; `src-tauri/src/lib.rs` registers commands and maintains the root registry.

Command surface:

```rust
register_workspace_root(path) -> WorkspaceRoot
unregister_workspace_root(root_id) -> ()
list_workspace_children(root_id, relative_path) -> Vec<WorkspaceEntry>
create_workspace_item(root_id, parent_relative_path, item_kind, name) -> WorkspaceEntry
rename_workspace_item(root_id, relative_path, new_name) -> WorkspaceMutation
trash_workspace_item(root_id, relative_path) -> WorkspaceMutation
load_workspace_mermaid(root_id, relative_path, mermaid_theme, color_theme) -> MermaidPreview
load_workspace_image(root_id, relative_path) -> ImagePreview
```

`WorkspaceMutation` returns old path, new path, and affected directory paths so the frontend can refresh and rewrite tabs accurately; deletes return the removed path prefix.

Path safety must be enforced in Rust, not only on the frontend:

- On pin, `canonicalize` first and accept only accessible real directories; store the canonical path under a backend-generated `rootId`.
- Later list and file ops accept only `rootId + relativePath`, never an arbitrary absolute target from the frontend.
- `relativePath` may contain only ordinary path components; reject absolute paths, `..`, platform prefixes, and empty names.
- When accessing an existing item, the canonicalized target must still lie inside the registered root.
- For create/rename targets, canonicalize the parent and confirm it remains inside the root, then join a single legal filename.
- Use `symlink_metadata` to detect and skip symlinks; directory scans, previews, renames, and deletes must not follow symlinks.
- Do not allow rename or Move to Trash on the pinned root itself.
- Writes use `create_new` and never overwrite.
- Move to Trash uses a Rust macOS Trash implementation, not `remove_file` or `remove_dir_all`; add a dedicated Trash dependency and wrap it inside the workspace module so business code never calls deletion primitives directly.
- Return stable error codes such as `outside_root`, `invalid_name`, `already_exists`, `not_found`, `permission_denied`, `unsupported_type`; the frontend maps them to user-readable copy and never shows Rust debug text.

Preview implementation:

- Markdown tree nodes continue to call existing `load_documents`; do not change Markdown security rendering.
- `.mmd` reads UTF-8 source and reuses `document.rs` `HeadlessRenderer`/Merman logic, returning the same safe HTML as Markdown Mermaid figures; on render failure still return an openable preview page with the error and safely escaped source.
- Images return a canonical path only after the backend confirms extension, regular file, root membership, and Tauri asset-protocol authorization; the frontend puts `convertFileSrc` into an `<img>` and never injects SVG or image bytes as inline HTML.
- Existing Markdown image authorization, dangerous-link blocking, and Mermaid SVG safety stay unchanged.

## 5. Implementation Order

1. Add sidebar/workspace persistence fields and general preview-tab foundations in `types.ts` / `state.ts`, with old-session compatibility tests first.
2. Create `workspace.rs`: root registration, path validation, shallow listing, filtering, create, rename, and Trash; register commands in `lib.rs`.
3. Extract a reusable native render entry for `.mmd`, and implement image preview metadata plus asset scope authorization.
4. Add pure `workspace.ts` / `status.ts` modules and unit tests.
5. Update `main.ts`: render Files/Open Tabs, lazy tree, context menus, name/delete dialogs, preview tabs, and status bar.
6. Extend theme switching, tab close, quick switch, recents, title, and refresh so all three preview kinds are handled safely.
7. Finish styles, keyboard accessibility, narrow-window truncation, and empty/error states.
8. Update README product positioning, supported workspace file types, file-op scope, and “no in-app editor / no continuous watching” notes.

## 6. Testing and Acceptance

Frontend unit tests:

- Old and new sessions restore; missing new fields use defaults.
- Root dedupe, expand-state persistence, directory sort, path-prefix rewrite.
- File/directory delete closes the right tabs and cleans recents.
- Status-bar content for Markdown, Mermaid, image, loading, error, and empty states.
- Unicode character counts, CJK/English word counts, size, time, and theme formatting.
- Quick switch, tab titles, and close logic do not regress for Mermaid/image tabs.

Rust unit tests with temp directories:

- Supported/unsupported extensions, hidden items, and symlink filtering.
- Roots, nested dirs, empty dirs, and sorting.
- Reject absolute paths, `..`, root escape, overwrite via rename, and illegal names.
- Create empty Markdown, create folders, same-kind extension renames.
- Affected-path results for file and directory renames.
- Successful Mermaid `.mmd` render, safe error page for invalid Mermaid, invalid UTF-8 errors.
- Image type validation and asset scope authorization.
- Trash logic tested via an adapter for path selection and error mapping; do not empty the user’s real Trash in automation.

Manual acceptance:

- Pin two folders; they and expand state survive restart.
- After create, rename, and Move to Trash deep in a tree, the tree and open tabs stay consistent immediately.
- Markdown, `.mmd`, and PNG/SVG all open in-app; Mermaid still zooms and exports.
- `.git`, ordinary source, binaries, and symlinks do not appear in the tree.
- Status bar, tree selection, menus, and confirmations stay readable in dark/light and all existing color themes.
- Layout works with top or left tabs, sidebar hidden/shown, and narrow windows.
- Run `pnpm check`, then verify a macOS Apple Silicon debug bundle.

## 7. Explicit Non-Goals

- No Markdown text editing, save, auto-created content templates, or undo/redo.
- No arbitrary file management outside pinned folders.
- No drag-move of files, copy/paste of files, bulk ops, full-text search, or continuous filesystem watching.
- Do not change existing Markdown security policy, native Merman rendering, macOS ARM targeting, or the current document-open path.
