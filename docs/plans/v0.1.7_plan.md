# MarkMaid v0.1.7 Implementation Plan

## 1. Decision summary

v0.1.7 is a focused command-and-reading-workflow release following the
published v0.1.6 workspace-polish release. It implements the five items selected
for this version:

1. a Command Palette for app commands while keeping `⌘P` dedicated to Quick
   Open;
2. a reversible Focus Mode for distraction-free reading;
3. actionable empty and error states with safe recovery operations;
4. reproducible performance fixtures and local development baselines; and
5. a macOS external-application selector with a preferred-app split button,
   similar to the Open With control in Codex.

The release must preserve MarkMaid's read-only boundary. Opening a file in
another application is an explicit handoff; MarkMaid does not observe, save, or
mediate edits made by that application. Full-text search remains the coherent
v0.2 candidate and must not be partially introduced through the performance
work.

Apple Developer ID signing and notarization remain outside this plan. The
existing Apple-Silicon, ad-hoc-signing release policy is unchanged.

## 2. Release outcomes

v0.1.7 is successful when:

- `⌘⇧P` opens one keyboard-first Command Palette that can execute the existing
  Open, Quick Open, export, appearance, tab, sidebar, Settings, Focus Mode, and
  external-open actions without duplicating their business logic;
- `⌘P` still opens Quick Open and never switches to command search;
- Focus Mode hides workspace/navigation chrome without changing the user's
  persisted sidebar, outline, or tab-placement preferences, and can always be
  exited by the same shortcut, the Command Palette, or a discoverable on-screen
  control;
- empty, unavailable, truncated, and failed states expose only valid recovery
  actions, retry through existing generation/cancellation contracts, and offer
  privacy-safe Copy Details output;
- a ready Markdown or Mermaid tab can be opened using a selected installed
  application, Finder, or a supported terminal destination through an explicit
  split-button menu;
- the selected external target survives restart by stable identifier, degrades
  safely when that application is uninstalled, and never persists an
  executable path or shell command;
- deterministic large-document, deep-workspace, many-tab, and multi-Mermaid
  fixtures can be generated locally and measured without adding production
  telemetry; and
- all v0.1.6 preview, cancellation, workspace, accessibility, export, print,
  diagnostics, and release behavior remains compatible.

## 3. Product boundary

### In scope

- A frontend command registry and one modal Command Palette.
- A native View-menu entry and `CmdOrCtrl+Shift+P` accelerator for the palette.
- Context-aware command visibility, enablement, shortcut labels, and disabled
  reasons.
- Runtime-only Focus Mode with preserved pre-focus reading preferences.
- Standard recovery actions for app-empty, workspace-empty, workspace-error,
  preview-error, Quick Open failure/truncation, export failure, and external-open
  failure states.
- A versioned, allowlisted Copy Details format that excludes contents and full
  paths.
- A titlebar split button for the preferred external application and a menu for
  choosing another installed target.
- Native macOS discovery and invocation of external applications through stable
  target IDs and bundle identifiers.
- File-opening targets for Markdown/Mermaid-capable editors and IDEs, Finder
  reveal, and explicitly supported terminal targets that open the containing
  folder.
- An optional session-v1 preference field for the selected external target, with
  compatibility and invalid-value tests.
- Deterministic generated performance fixtures, benchmark commands, a documented
  baseline environment, and non-flaky smoke assertions.

### Explicitly out of scope

- Favorites, bookmarks, highlights, notes, or persisted reading history.
- Named workspace sets or Workspace Switcher.
- Full-text search, excerpts, backlinks, broken-link reports, or a persistent
  content index.
- Editing, saving, autosave, conflict resolution, or monitoring external-editor
  changes.
- Continuous filesystem watching or background indexing.
- Arbitrary user-provided executables, command templates, shell snippets, CLI
  flags, environment variables, or working-directory scripts.
- Persisting application bundle paths or icon file paths.
- Installing, downloading, updating, or configuring external applications.
- Treating every macOS application as a text editor; only validated discovered
  handlers and explicit built-in destinations are shown.
- Persisting Focus Mode, palette queries, result selection, copied details, or
  performance measurements in the production session.
- Performance optimizations without a reproduced measurement and separately
  reviewed acceptance target.
- A frontend framework migration, cross-platform support, Developer ID signing,
  or notarization.

## 4. Current-state assessment

| Area | Current state | v0.1.7 implication |
| --- | --- | --- |
| Shortcuts | Native menus emit dedicated events; `⌘P` is Quick Open and frontend key handling mirrors several accelerators | Add one native palette event/accelerator and route both native and WebView triggers to the same controller action |
| Commands | Actions are bound directly in `main.ts`, native menu handlers, and domain controllers | Introduce a typed registry that delegates to existing actions; do not reimplement export, navigation, appearance, or workspace behavior |
| Overlays | `overlay-controller.ts` owns Quick Open/Find visibility and focus restoration; export/workspace dialogs have their own controllers | Add palette exclusivity and focus lifecycle through the existing overlay seam rather than another global boolean cluster |
| Focus | Stable focus keys survive full-shell rendering; local overlays trap and restore focus | Focus Mode must retain this behavior and provide deterministic fallback when hidden chrome owned focus |
| Shell chrome | Titlebar, top tabs, left sidebar, right outline, and status bar are rendered from `main.ts` | Model Focus Mode explicitly and omit hidden controls from the accessibility tree; do not overwrite persisted visibility settings |
| Empty/error UI | The app empty state has Add Folder/Open; preview errors have Try Again/Open Another; workspace notices are mostly plain text | Replace string-driven recovery UI with typed actionable-state models and consistent buttons/menu commands |
| Details/diagnostics | v0.1.6 has privacy-safe diagnostic normalization and clipboard fallback | Reuse the allowlist philosophy, not raw error messages or paths, for Copy Details |
| External open | Tauri opener can reveal a path and open URLs; no installed-app discovery or remembered selection exists | Add a narrow macOS native module for discovery/icon extraction/launch; keep the frontend contract typed and identifier-based |
| Persistence | Session v1 already accepts optional forward-compatible fields; Focus Mode does not exist | Add only an optional bounded external target ID; keep Focus Mode and palette state runtime-only |
| Performance | Unit/regression fixtures exist but there is no benchmark command or recorded baseline | Generate deterministic large fixtures outside Git, separate benchmarks from the normal gate, and keep a fast structural smoke check in CI |

## 5. Contracts to establish before implementation

### 5.1 Command registry contract

Add a pure command model owned by `src/commands.ts`:

```text
CommandId = stable string union

AppCommand {
  id
  label
  section
  keywords
  shortcutLabel?
  availability(context) -> hidden | disabled(reason) | enabled
  execute(context) -> void | Promise<void>
}
```

Rules:

- IDs are compile-time-known and stable across renders. User input never becomes
  a command ID.
- Labels and keywords are static application strings. Document names, paths,
  source text, workspace names, and recent entries are not command results.
- `availability` is evaluated against a fresh context when results render and
  again immediately before execution; a stale result cannot export or open a
  tab that is no longer active.
- Disabled commands remain searchable when their presence explains a shortcut
  or feature, and expose a concise reason. Commands with no meaning in the
  current product configuration may be hidden.
- Command execution delegates to controllers/reducers already responsible for
  the action. The registry must not mutate imported `main.ts` bindings.
- Executing a command closes the palette before navigation/render unless the
  command explicitly opens a replacing modal. Focus transfers to the new modal
  or to the command's resulting stable shell target.
- Rejected async commands use the existing diagnostic normalization and
  actionable notice pattern.
- A failed command does not reopen the palette automatically; Retry is exposed
  in the resulting actionable state where appropriate.

Minimum command catalog:

| Section | Commands |
| --- | --- |
| File | Open Preview Files, Add Folder, Quick Open, Export Document, Reload Document, Reveal in Finder |
| External | Open in Preferred Application, Choose External Application |
| Tabs | Close Tab, Reopen Closed Tab, Next Tab, Previous Tab, Move Tab Left, Move Tab Right |
| View | Toggle Focus Mode, Show/Hide Sidebar, Show/Hide Outline, Tabs on Top, Tabs on Left |
| Appearance | Use System Appearance, Use Light Appearance, Use Dark Appearance, each color palette |
| Application | Settings, Copy Diagnostics when Settings is active |

Do not add commands for unimplemented roadmap candidates. Dynamic recent-file
or workspace-file search remains Quick Open's responsibility.

### 5.2 Command Palette interaction contract

Open the palette from:

- `CmdOrCtrl+Shift+P` in the native View menu;
- the same WebView shortcut as a fallback when focus is inside editable/search
  controls; and
- an optional title/menu command entry, without adding a permanent new toolbar
  button in v0.1.7.

Interaction:

- Opening the palette fully dismisses Quick Open, Find, export, and other
  replaceable overlays through their controller close/cancel hooks.
- Capture one stable shell focus key before opening and restore it on Escape or
  backdrop dismissal when still valid.
- Use an accessible dialog containing a combobox and listbox. Expose active
  result with `aria-activedescendant`, result sections with text labels, and
  disabled reasons to assistive technology.
- Arrow Up/Down move by one enabled result; Home/End move to boundaries; Enter
  executes; Escape closes; Tab remains trapped inside the dialog.
- Ignore global palette shortcuts during IME composition.
- An empty query shows a deterministic recommended subset, with Focus Mode,
  Open, Quick Open, and the current contextual action ahead of less-used
  settings.
- Search is case-insensitive Unicode-normalized token/subsequence matching over
  label, section, and keywords. It is deterministic and dependency-free unless
  a measured need justifies a small library.
- Exact label prefix outranks keyword matches; stable catalog order breaks ties.
- Cap visible results at 50 and keep selection by command ID as filtering
  changes.
- Empty results show “No matching commands” and never fall through to Quick
  Open.
- Keep `⌘P` unchanged. Pressing it while the palette is open replaces the
  palette with Quick Open and preserves the original shell focus target.

### 5.3 Focus Mode contract

Focus Mode is a runtime presentation mode, not a saved preference.

- Add `focusMode: boolean` to live application/shell state with a default of
  `false`; omit it from `PersistedSessionV1` serialization.
- Entering Focus Mode does not modify `leftSidebarVisible`,
  `tableOfContentsVisible`, `tabPlacement`, `sidebarView`, or widths.
- Exiting restores the same reading chrome implied by those preferences,
  including changes made before Focus Mode entered.
- In Focus Mode hide the left sidebar, right outline, tab strip/tab sidebar,
  ordinary titlebar action groups, and status bar. Retain the native traffic
  lights, a minimal drag region/document title, the content stage, document
  search, and transient notices required for errors.
- Hidden controls are omitted from markup or marked inert/hidden; CSS opacity
  alone is insufficient because controls must leave the tab order and
  accessibility tree.
- Provide a small “Exit Focus Mode” control that appears on keyboard focus or
  pointer movement near the titlebar and does not cover document content at
  200% zoom.
- Toggle with `CmdOrCtrl+Shift+F`, the Command Palette, and the View menu. Avoid
  the macOS `Ctrl+Cmd+F` full-screen shortcut.
- Escape exits Focus Mode only after higher-priority transient UI is handled:
  viewer/dialog/palette/Quick Open/Find/context menu first, then Focus Mode.
- If focus was on chrome that becomes hidden, move it to the active preview
  heading/content region; if there is no preview, focus the empty-state heading.
- Announce “Focus Mode on/off” once through the dedicated polite status region.
- Drag/drop opening, native menu commands, external-change notices, and print
  windows continue to work while Focus Mode is active.

### 5.4 External application selector contract

#### User interface

For a ready Markdown or Mermaid tab, render a compact titlebar split button:

- the primary segment shows the preferred target's icon and accessible name;
- activating the primary segment opens the active file using that target;
- the chevron opens a keyboard-accessible menu of current valid targets;
- if no preference exists, activating the primary segment opens the menu rather
  than silently choosing an application;
- selecting a target both opens the file and makes it the new preference;
- include **System Default** and **Reveal in Finder** explicitly;
- list discovered file handlers alphabetically after the current preference;
- list supported terminal destinations in a separate section and label their
  behavior “Open containing folder in …”;
- show a checkmark on the preference and app icons at a bounded 32×32 logical
  size;
- expose the same Open/Choose actions in the Command Palette and tab context
  menu.

Do not show the control for Settings, loading/error tabs, or images in the first
cut. Image handoff remains Reveal in Finder; supporting image editors can be a
later extension after the text workflow is verified.

#### Native contract

Add `src-tauri/src/external_apps.rs` with typed commands:

```text
list_external_open_targets(path) -> ExternalOpenTarget[]
open_external_target(path, targetId) -> ExternalOpenResult

ExternalOpenTarget {
  id
  displayName
  kind: systemDefault | application | finder | terminal
  openMode: file | reveal | containingDirectory
  iconPngBase64?
}
```

Native rules:

- Canonicalize `path`, require an absolute regular supported Markdown/Mermaid
  file, and reject symlinks or unsupported entries under the same policy used
  by direct preview loading.
- Discover applications through macOS Launch Services/`NSWorkspace` for the
  current file URL. Filter MarkMaid itself, invalid bundles, duplicates, and
  targets without a stable bundle identifier.
- Add Finder and known terminal destinations through a native allowlisted
  adapter registry. Hide a destination when its application or supported launch
  mode is unavailable.
- The frontend sends only the opaque target ID returned by the native list.
  Resolve bundle ID, application URL, open mode, and containing directory again
  natively at execution time.
- Use native workspace/open APIs with argument arrays. Never concatenate or
  execute a shell string and never accept an executable path, CLI flag, or
  command template from the frontend.
- Application discovery and opening must not read document contents.
- Convert app icons to bounded PNG data in memory. Do not widen asset scope or
  return application bundle/icon paths to the WebView.
- Cap results (for example, 32 targets), icon dimensions, and encoded icon bytes.
- Return stable error codes such as `file_unavailable`, `target_unavailable`,
  `unsupported_target`, and `open_failed`; arbitrary native error prose is not
  persisted or copied.
- App inventory, icons, and launch failures remain local and are never added to
  diagnostics or telemetry.

#### Preference and fallback

- Persist only `externalOpenTargetId?: string` as an optional bounded
  session-v1 field. Do not persist app paths, bundle paths, display names,
  icons, or discovery results.
- Validate allowed length/characters during restore; invalid values become
  unset.
- If the preferred target is not returned for the active file, retain the saved
  ID for possible reinstall but render an unavailable state. The primary button
  opens the chooser; it must not fall back silently.
- System Default is a real selectable preference with a stable built-in ID.
- Finder/terminal selection may be remembered, but the primary button's
  accessible label must say whether it opens the file or its containing folder.
- Opening externally never closes the MarkMaid tab, changes history, grants new
  asset scope, or starts file watching.

### 5.5 Actionable-state contract

Introduce a pure `ActionableStateModel` rather than inferring actions from
rendered error strings:

```text
ActionableState {
  area
  code
  title
  detail
  severity
  actions: ActionId[]
}
```

Action IDs map to typed controller operations. Unknown combinations fail closed
with no destructive action.

Minimum state/action matrix:

| State | Required actions |
| --- | --- |
| No tabs / no roots | Add Folder, Open Preview Files, Open Command Palette |
| No tabs / roots exist | Quick Open, Open Preview Files, Add Folder |
| Empty compatible root/folder | Refresh, Reveal in Finder; Remove Root only for a root |
| Root unavailable or listing failed | Retry, Remove Root, Copy Details; Reveal only when the path still resolves |
| Preview load error | Retry, Reveal in Finder, Open Another, Copy Details |
| Quick Open index failed | Retry Index, Copy Details; existing tab/recent results remain usable |
| Quick Open truncated | Continue with Partial Results, Refresh, Copy Details; truncation is not styled as a fatal error |
| Export failed | Retry Export when the original ready tab still exists, Copy Details |
| External open failed | Retry, Choose Another Application, Reveal in Finder, Copy Details |

Behavior rules:

- Retry invalidates/cancels the prior task generation before starting a new one.
- Retry buttons disable while their replacement request is active and prevent
  duplicate submissions.
- Reveal and Remove Root reuse existing workspace/preview validation. Remove
  Root always confirms that it unregisters app metadata only and never deletes
  files or closes unrelated tabs.
- Actions unavailable because state changed disappear or become disabled before
  execution; stale callbacks revalidate state.
- Preserve useful partial results and the last ready preview whenever the
  existing v0.1.6 contract already does so.
- Every action is keyboard reachable, has a visible focus indicator, and returns
  focus to a deterministic surviving control after render.
- Short outcomes are announced once; do not make the entire content stage live.

Copy Details uses a deterministic allowlisted format:

```text
MarkMaid issue details v1
App: MarkMaid <version>
Area: <preview|workspace|quick-open|export|external-open>
Code: <normalized-code>
State: <loading|error|unavailable|truncated>
Recoverable: <yes|no>
```

Never include document/workspace contents, rendered HTML/SVG, filenames, full
paths, recent entries, queries, clipboard data, app inventory, app bundle paths,
or raw native error messages. The local on-screen state may continue showing a
filename/path when useful; Copy Details is privacy-safe by default.

### 5.6 Performance fixture and baseline contract

Performance work measures current behavior before optimizing it.

Add a deterministic generator with a fixed seed and manifest for:

- **large Markdown:** an 8 MiB file below the existing 16 MiB limit containing
  headings, paragraphs, tables, task lists, code fences, math, links, local
  image references, and Mermaid fences;
- **deep workspace:** thousands of supported Markdown paths across nested
  folders plus hidden/noise directories, unsupported files, duplicate names,
  and separate depth/entry-cap cases;
- **many tabs:** pure frontend state for 10, 50, 100, and 200 mixed tab records;
- **multi Mermaid:** batches of 1, 10, and 50 representative diagrams,
  including theme rerender input;
- **command catalog:** synthetic catalogs up to 500 commands to prove filtering
  remains comfortably below the real catalog size.

Rules:

- Generate large files into a gitignored directory; commit only the generator,
  small templates, manifest, and expected structural counts.
- `pnpm perf:fixtures` is idempotent and can recreate the same byte counts and
  tree shape.
- Add frontend benchmarks for command filtering, many-tab shell/view-model
  derivation, and other factored pure operations.
- Add Rust benchmarks for Markdown render, workspace scan/index, and Mermaid
  batch/theme render using release-mode code.
- `pnpm perf:baseline` runs benchmarks explicitly and writes local JSON under
  `artifacts/performance/`; it is not part of app startup and never uploads.
- Record hardware, macOS, architecture, build profile, fixture manifest hash,
  median, and p95 in `docs/performance/v0.1.7.md`. Do not record user file paths
  or document data.
- Run at least one warm-up and five measured iterations. Clearly distinguish
  cold filesystem work from warmed process/cache behavior.
- Do not fail normal CI on wall-clock benchmark variance. `pnpm check` runs a
  fast structural smoke test that validates fixture caps, bounded results,
  cancellation, and absence of runaway work.
- After the first baseline is captured, set reviewed regression budgets before
  landing any optimization. A budget must be the larger of a justified absolute
  floor and measured baseline plus documented tolerance.
- Command Palette filtering for the real catalog should target one animation
  frame (16 ms) on the release machine; external target discovery should show a
  loading state after 100 ms and finish or expose Retry by a bounded timeout.
- No production telemetry, persistent timing history, background profiler, or
  automatic benchmark upload is introduced.

## 7. Test plan

### Frontend unit tests

- stable command IDs, sections, search normalization, ranking, result cap,
  disabled reasons, fresh-context revalidation, and catalog determinism;
- palette open/replace/close focus lifecycle, IME behavior, keyboard reducers,
  selection retention, empty results, and async failure handling;
- shortcut precedence proving `⌘P` Quick Open, `⌘⇧P` palette, `⌘F` Find,
  `⌘⇧F` Focus Mode, and macOS full-screen remain distinct;
- Focus Mode does not modify persisted sidebar/outline/tab settings, is omitted
  from session snapshots, and chooses stable focus fallbacks;
- external target loading, cache invalidation, preference selection, missing
  target fallback, split-button labels, and no auto-fallback;
- optional session-v1 target-ID validation, old-session restore, new-session
  round trip, invalid-value fallback, and rollback tolerance;
- actionable-state matrices, stale-action revalidation, retry deduplication,
  destructive-action confirmation, focus restoration, and announcement count;
- Copy Details allowlist/adversarial privacy coverage;
- deterministic fixture generation manifest/count/hash tests and performance
  smoke bounds.

### Rust unit tests

- installed-handler discovery dedupes bundle IDs, excludes MarkMaid, sorts
  deterministically, and enforces result/icon bounds;
- file validation rejects relative paths, directories, unsupported types,
  symlinks, missing files, and changed paths;
- target validation rejects unknown/stale IDs and never interprets input as a
  command, executable, flag, or bundle path;
- Finder uses reveal semantics, file handlers receive the file URL, and terminal
  adapters receive only the containing directory;
- target disappearance between list and open returns `target_unavailable`;
- icon conversion returns bounded in-memory PNG data without paths;
- external commands serialize to the exact TypeScript tagged result shape;
- performance fixtures exercise existing size, depth, entry, symlink, hidden,
  and cancellation limits without weakening them;
- native menu routing includes Command Palette and Focus Mode and preserves all
  existing accelerators.

### Integration and regression tests

- open/close/replace palette with Quick Open, Find, export, workspace dialogs,
  viewer, and context menus; no overlay leaves stale focus or background work;
- execute every catalog command in enabled and disabled contexts and compare it
  with its existing direct UI/native-menu behavior;
- enter/exit Focus Mode from top-tab and left-tab layouts, empty state, ready
  previews, loading/error states, and active notices;
- choose several installed editors, restart, reopen, uninstall/simulate missing,
  and recover through Choose Another/Finder;
- verify external edits do not mutate MarkMaid state until the existing explicit
  Reload path is used;
- exercise Retry/Reveal/Remove/Copy Details for representative workspace,
  preview, Quick Open, export, and external errors;
- rerun v0.1.6 cancellation races, theme rerender, workspace reorder,
  diagnostics privacy, keyboard navigation, export, PDF/print, and local asset
  bounds;
- generate/run all performance fixtures and record baseline output on the
  release machine.

### Quality gates

- `CI=true pnpm check` passes TypeScript, Vitest, Vite, Rust tests, rustfmt, and
  Clippy.
- `CI=true pnpm perf:smoke` passes deterministic structural and bounded-work
  checks; wall-clock benchmarks remain an explicit non-CI gate.
- `CI=true pnpm tauri build --debug --bundles app --target
  aarch64-apple-darwin` produces a runnable debug app.
- `git diff --check` passes.
- No shell plugin, arbitrary executable permission, content index, watcher,
  telemetry endpoint, or benchmark fixture is present in the production bundle.
- Version metadata, README, changelog, Roadmap, release notes, and checklist
  agree before tagging.

## 8. Manual QA matrix

### Command Palette

1. Open from native menu and `⌘⇧P`; confirm `⌘P` still opens Quick Open.
2. Search by label, section, keyword, and shortcut; verify stable ordering and
   disabled reasons.
3. Execute every command from valid and invalid tab/workspace states.
4. Replace palette with Quick Open/export/Settings and confirm original focus
   restoration and no double live announcement.
5. Test keyboard-only and VoiceOver combobox/listbox behavior, IME input, 200%
   zoom, reduced motion, and all palettes.

### Focus Mode

1. Enter with top and left tab placement and with sidebars/outline initially
   shown and hidden.
2. Confirm content width expands, hidden chrome leaves the tab order, and the
   native drag region/traffic lights remain usable.
3. Exit with shortcut, Command Palette, Exit control, and Escape after closing
   higher-priority overlays.
4. Restart while Focus Mode is active and confirm ordinary persisted chrome is
   restored rather than Focus Mode.
5. Open files, Find, export, print, receive external-change notices, and use
   drag/drop while focused.

### External application selector

1. Test no preference, System Default, at least two installed editors/IDEs,
   Finder, and every detected supported terminal destination.
2. Verify primary icon/name/menu checkmark, keyboard navigation, VoiceOver
   labels, dark/high-contrast appearance, and missing icons.
3. Select an app, restart, and confirm preference restoration by ID.
4. Remove/simulate removal of the preferred app; confirm chooser fallback with
   no silent substitution.
5. Rename/move/delete the active file between discovery and activation; confirm
   a bounded actionable error.
6. Confirm editor changes never auto-refresh or save through MarkMaid and become
   visible only through explicit Reload.
7. Confirm no app bundle/executable/icon path appears in diagnostics or copied
   issue details.

### Actionable states

1. Exercise every row in the state/action matrix with keyboard and pointer.
2. Trigger rapid repeated Retry and confirm one current request and silent
   cancellation of superseded work.
3. Remove an unavailable root and confirm files remain on disk and open tabs
   stay intact.
4. Paste Copy Details into plain text and inspect the exact allowlisted fields.
5. Confirm partial Quick Open results stay usable when a root fails or truncates.

### Performance

1. Regenerate fixtures twice and compare manifest hashes/counts.
2. Run cold and warmed baseline commands on the release machine.
3. Confirm output records environment/methodology without user paths or data.
4. Open the generated large document/workspace interactively and confirm the UI
   communicates loading/truncation and remains cancellable.
5. Confirm the production app/DMG does not contain generated fixtures or local
   benchmark JSON.

## 9. Performance and resource rules

- The real command catalog is expected to remain below 250 entries; visible
  palette results are capped at 50 and filtering must be linear in catalog text
  size.
- External discovery returns at most 32 targets and bounded icons; one in-flight
  discovery exists per current path and stale results are discarded by
  generation token.
- External target/icon cache is process-local and bounded. It is cleared on
  target refresh and never written to session storage.
- Focus Mode must not duplicate document DOM or rerender Markdown merely to hide
  chrome.
- Actionable retries reuse v0.1.6 cancellation/task tracking and may not create
  parallel work for the same state key.
- Keep existing 16 MiB text, 100 MiB image, workspace depth/entry, Quick Open
  result, and print timeout limits unchanged unless a measured plan amendment
  explicitly changes one.
- Benchmarks run in release mode where applicable and never execute automatically
  for ordinary users.

## 10. Migration and rollback

- Persisted session remains version 1. Add only the optional bounded
  `externalOpenTargetId` field.
- Pre-v0.1.7 sessions restore with no external preference. Invalid or unknown
  IDs are safe and do not prevent session restoration.
- A v0.1.6 rollback ignores the extra optional JSON field and restores all
  existing tabs/workspace/preferences.
- Focus Mode, palette state, app discovery/icons, actionable copies, and
  performance output require no migration or cleanup.
- If external-app native support must be reverted, remove its UI/commands and
  leave the ignored optional preference harmlessly in the stored session.
- Do not bump the app version until the documentation/release workstream owns
  the final synchronized v0.1.7 version change.

## 11. Risk register

| Risk | Mitigation |
| --- | --- |
| Command Palette becomes a second Quick Open | Static app-command catalog only; no document/workspace/recent results; preserve `⌘P` |
| Command execution uses stale state | Recompute availability immediately before execute and delegate to current controllers |
| Overlay replacement loses focus or leaks work | Reuse stable focus sessions and cancellation-aware exclusivity hooks |
| Focus Mode makes the app appear broken | Runtime-only state, native View command, reversible shortcut, discoverable Exit control, one announcement |
| Hidden chrome remains accessible | Omit/inert hidden controls and test tab order/VoiceOver instead of opacity-only CSS |
| External target input becomes command injection | Opaque allowlisted target IDs, native re-resolution, no shell string/plugin/arbitrary executable |
| Installed-app discovery leaks paths or inventory | Return bounded display/icon data only, keep it local/in memory, exclude from diagnostics/details |
| Preferred app disappears | No silent fallback; open chooser with actionable target-unavailable state |
| Terminal destinations behave inconsistently | Per-app native adapters and capability tests; hide unsupported adapters |
| Retry starts duplicate native work | Existing generation tokens plus best-effort cancellation and disabled pending actions |
| Copy Details leaks local information | Versioned allowlist formatter and adversarial privacy tests |
| Benchmark timings make CI flaky | Separate explicit baseline from structural CI smoke; review budgets after measured baseline |
| Performance scope turns into v0.2 indexing | Generated fixtures and measurement only; no production index/cache/search path |

## 12. Delivery order

Implement as small reviewable commits in this order:

1. command/shortcut characterization tests and command registry;
2. Command Palette controller, markup, focus, and existing-command wiring;
3. Focus Mode state, shell view model, shortcut/menu, and accessibility;
4. external-app native discovery/launch contracts and Rust tests;
5. external-app frontend controller, preference, split button, palette/context
   commands, and failure states;
6. shared actionable-state model and privacy-safe Copy Details conversion;
7. deterministic performance generators, benchmarks, smoke checks, and initial
   baseline document;
8. full regression/manual QA and documentation/release preparation.

Do not combine native external-app launch code with a broad shell capability or
with performance optimization. If an application requires an unsafe/custom
command adapter, omit it from v0.1.7 and amend the plan rather than weakening
the target contract.
