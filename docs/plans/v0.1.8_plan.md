# MarkMaid v0.1.8 Implementation Plan

## 1. Decision summary

v0.1.8 is an **engineering-foundation** release. It does not ship a new
user-facing reading workflow. Instead it hardens the seams that v0.1.9 and later
feature releases depend on:

1. a **typed frontend ↔ Rust command contract** so invoke payloads and results
   fail at generation or compile time when fields or tagged variants drift;
2. a **session migration test harness** that covers every persisted-session
   schema change, including the soft defaults used today; and
3. a continued **shell decomposition** of `src/main.ts` so the composition root
   stops owning Quick Open UI, Command Palette HTML, workspace tree chrome, and
   Find highlighting while retaining bootstrap and cross-domain wiring.

v0.1.9 will consume these foundations for Favorites, reading history,
bookmarks / highlights / notes, and UI localization. Those features are
explicitly out of scope here.

Apple Developer ID signing and notarization remain outside this plan. The
existing Apple-Silicon, ad-hoc-signing release policy is unchanged.

## 2. Release outcomes

v0.1.8 is successful when:

- every Tauri command used by the frontend is described by a single typed
  contract; renamed fields, missing arguments, and mismatched tagged-result
  variants fail during type generation or TypeScript/Rust compilation rather
  than at runtime;
- loading and saving the parsed `session` Store value go through an explicit
  `migrateSession` pipeline with unit tests for invalid values, unknown
  versions, legacy `version: 1` fixtures, optional-field defaults, and
  forward-compatible ignored fields; Store-file parse/open failure is handled
  separately at bootstrap;
- `src/main.ts` is primarily a composition root (bootstrap, `commit`, native
  event wiring, and thin render orchestration) while Quick Open rendering,
  Command Palette rendering, workspace tree / dialog UI, document Find UI, and
  any additional Settings/status extraction required to reach the line-count
  gate lives behind tested modules;
- all v0.1.7 preview, Command Palette, Focus Mode, external handoff, export,
  cancellation, accessibility, and session-v1 runtime behavior remains
  compatible; and
- README / changelog / roadmap updates describe the foundation theme without
  claiming new reading features.

## 3. Product boundary

### In scope

- Generate typed invoke bindings for every command in the single Specta command
  registry that replaces `generate_handler![…]`.
- Align TypeScript argument and result types with Rust `Serialize` /
  `Deserialize` shapes (`camelCase`, tagged enums such as `TaskOutcome`).
- Introduce a pure parsed-value load path: migrate/validate →
  `fromPersistedSession`, plus save-path serialization that always writes the
  current schema version.
- Add fixture-driven migration tests under the frontend (and Rust if any
  native session helpers appear) covering every field currently on
  `PersistedSessionV1` and every soft default.
- Extract remaining large UI domains from `main.ts` into `src/app/` (or sibling
  modules) without changing visual design or adopting a frontend framework.
- Keep the stored session schema exactly at version 1; do not add or rename
  persisted fields. Favorites/history/annotation fields land in v0.1.9.

### Explicitly out of scope

- Favorites, bookmarks, highlights, notes, or persisted visit / closed-tab
  history (v0.1.9).
- UI language switching or string catalog localization (v0.1.9; this release may
  only make strings easier to find by extraction).
- Workspace Switcher, full-text search, backlinks, broken-link reports.
- Built-in editing, continuous filesystem watching, plugins, cloud sync.
- Performance optimizations that are not required to keep existing budgets /
  smoke checks green after the refactor.
- A frontend framework migration, cross-platform support, Developer ID signing,
  or notarization.
- Changing the public product behavior of Command Palette, Focus Mode, Quick
  Open ranking, or external-app handoff beyond equivalent refactors.

## 4. Verified baseline (PR review, 2026-08-12)

| Area | Current state | v0.1.8 implication |
| --- | --- | --- |
| IPC typing | 25 unique commands are registered in `src-tauri/src/lib.rs`; the frontend has 26 raw `invoke(...)` call sites across `src/main.ts`, `src/export.ts`, `src/print.ts`, `src/code-block.ts`, and `src/diagram-viewer.ts` | Replace all 26 call sites; raw `invoke` remains only in generated output |
| Specta / codegen | Not present in `package.json` / `Cargo.toml`; Tauri is v2 | Use the pinned, published Tauri 2 stack in §5.1; there is no fallback implementation in this release |
| Session schema | `PersistedSessionV1` with `version: 1`; `isPersistedSession` accepts only `version === 1`; soft defaults in `fromPersistedSession` | Keep `version: 1` exactly; add an explicit migrator + tests without renaming persisted fields |
| Legacy fields | `mermaidTheme?` typed but unread on restore | Document and test ignore / one-time normalize behavior inside the migrator |
| Runtime-only state | `focusMode`, `closedTabsHistory`, `documentVisitHistory` reset on load | Do not persist them in v0.1.8; migration tests assert they stay runtime-only |
| Shell size | `src/main.ts` is 5,832 lines; controllers already exist for preview, navigation, overlays, palette state, export, external apps, workspace tasks, and persistence | Extract the four named UI domains in §5.3; do not invent another state owner |
| Commands | `src/commands.ts` catalog already typed for palette IDs | Leave catalog behavior unchanged; only relocate wiring / HTML as needed |
| i18n | English string literals throughout TS and native menus | Keep strings beside their newly extracted views; catalog extraction and translation begin in v0.1.9 |

## 5. Contracts to establish before implementation

### 5.1 Typed frontend ↔ Rust command contract

**Locked approach:** generate and commit TypeScript bindings from Rust with the
published Tauri 2 Specta stack:

```toml
tauri-specta = { version = "=2.0.0-rc.21", features = ["derive", "typescript"] }
specta = { version = "=2.0.0-rc.22", features = ["derive", "function"] }
specta-typescript = "=0.0.9"
```

These versions are mutually compatible according to the published
`tauri-specta 2.0.0-rc.21` crate metadata and support Tauri 2. Do not use a Git
dependency or silently fall back to a second emitter. If this exact stack
cannot compile against the locked MarkMaid dependencies, stop the release and
revise this plan in a dedicated PR instead of landing a half-typed contract.
Compatibility references: the
[Tauri Specta v2 support matrix](https://github.com/specta-rs/tauri-specta#getting-started)
and the published
[`tauri-specta 2.0.0-rc.21` crate](https://crates.io/crates/tauri-specta/2.0.0-rc.21).

Implementation shape:

- add `src-tauri/src/ipc.rs` with one `command_builder()` using
  `tauri_specta::collect_commands![...]`; `src-tauri/src/lib.rs` uses
  `builder.invoke_handler()` instead of a separate `generate_handler![...]`
  list, so the runtime registry and generated catalog cannot diverge;
- annotate every command with `#[specta::specta]` and derive `specta::Type` on
  every serialized command input/result/error DTO;
- commit generated output at `src/generated/tauri-bindings.ts` and never edit
  it manually;
- add `src/ipc.ts` with one tested generic `unwrapCommandResult` helper for the
  `{ status: "ok", data } | { status: "error", error }` unions generated from
  Rust `Result<T, E>`. It returns `data` or throws the typed error so existing
  controller `try/catch` behavior remains intact; it contains no command names
  and is not a second binding layer;
- add `src-tauri/src/bin/export-bindings.rs` with `--check` and write modes;
  `pnpm ipc:generate` rewrites the committed file and `pnpm ipc:check` generates
  to a temporary path and byte-compares it; and
- run `pnpm ipc:check` near the start of `scripts/check.sh`, before TypeScript
  build/tests, so stale generated bindings fail the normal quality gate.

Hand-maintained interfaces in `src/types.ts`, `src/external-apps.ts`, and
`src/diagnostics.ts` are removed only when they duplicate an IPC DTO. Domain and
UI state types remain hand-written and import/re-export generated DTOs where
appropriate.

Rules:

- Every command in the single `command_builder()` appears in generated output.
  Adding a Rust command without regenerating bindings fails `pnpm ipc:check`.
- Argument and result types use the same `camelCase` serde rename rules as
  today. Tagged enums such as `TaskOutcome` / cancellation results must be
  represented as discriminated unions in TypeScript.
- Frontend call sites import `commands` from
  `src/generated/tauri-bindings.ts` and use `unwrapCommandResult` only for Rust
  `Result` commands; no handwritten command wrapper or second command-name list
  is introduced.
- Privacy-sensitive fields (paths, filenames, document bodies) remain allowed in
  typed payloads where the product already sends them; the contract does not
  broaden what is logged or copied into diagnostics.
- Generated bindings are committed. Regeneration and drift-check commands are
  documented in `docs/RELEASING.md`.

Acceptance:

- `rg -n '\binvoke(?:<[^>]+>)?\(' src --glob '*.ts'` reports only the generated
  binding file.
- Changing a Rust result field without regenerating makes `pnpm ipc:check`
  fail; regenerating then makes affected TypeScript call sites fail `pnpm
  build` until updated.
- All 25 registered commands compile through generated call sites, covering all
  26 original frontend call sites; the existing critical flows (`reload_document`, `index_workspace_markdown`,
  `list_external_open_targets`, `print_export_html`, and
  `cancel_background_task`) retain their current tests/smokes.
- `src/ipc.test.ts` covers generated-result success, string errors, structured
  errors, and a transport-level rejected Promise without stringifying or
  discarding the error payload.

### 5.2 Session migration harness

Add a pure `src/session/migrate.ts` module and keep Store I/O in
`src/app/persistence.ts`. The store plugin already returns a parsed JavaScript
value, so the migration layer does **not** parse the on-disk JSON file. It owns:

```text
migrateSession(candidate: unknown) -> PersistedSessionCurrent | null
fromPersistedSession(session: PersistedSessionCurrent | null) -> AppState
toPersistedSession(state: AppState) -> PersistedSessionV1
```

Rules:

- `version` is mandatory and exactly `1`. Unknown/missing/future versions return
  `null`, and `fromPersistedSession(null)` produces a fresh `DEFAULT_STATE`.
- Current stored schema remains exactly `version: 1` for v0.1.8. Refactors must
  preserve persisted field names; no schema bump is allowed in this release.
- Every optional field on `PersistedSessionV1` has a table-driven test asserting
  the current default when missing.
- Invalid tab entries are dropped individually; valid entries survive. Preview
  paths must be non-empty absolute macOS paths, `scrollTop` must be finite and
  is clamped to `>= 0`, duplicate preview keys keep the first entry, and a
  missing/removed `activeTabKey` falls back to the last surviving tab.
- Migration performs no filesystem I/O and no `canonicalize` call. Paths that
  were canonical when saved remain unchanged; existence is checked only by the
  existing preview/workspace restore paths.
- `recentDocuments` uses the existing order-preserving dedupe and cap of 10;
  invalid `externalOpenTargetId` values normalize to `null`; workspace roots,
  expanded paths, widths, fonts, palettes, and themes use the existing
  production normalizers.
- Legacy `mermaidTheme` is ignored because the current light/dark fields already
  default independently; a fixture locks that behavior.
- Save path always writes the current schema through `toPersistedSession` /
  equivalent; tests round-trip a full fixture.
- No production telemetry or new diagnostics field. Invalid Store values fall
  back to defaults; only an underlying Store-open failure produces the single
  privacy-safe bootstrap notice described below.

Minimum fixture set:

| Fixture | Expectation |
| --- | --- |
| `undefined`, `null`, array, or non-object Store value | Defaults |
| `{ version: 2, … }` (future) | Defaults / rejected |
| Minimal v1 `{ version: 1, tabs: [], activeTabKey: null, theme: "system" }` | Valid; optional fields defaulted |
| Full v1 with every optional field | Round-trip equality on normalized form |
| Legacy `mermaidTheme` only | Ignored; current light/dark defaults applied; no crash |
| One corrupt tab among valid tabs | Corrupt entry dropped; valid entries and active-key reconciliation retained |
| Oversized `recentDocuments` | Truncated to existing max (10) |

Malformed **on-disk** `markmaid-state.json` is a Store-open failure before this
module runs. v0.1.8 adds an explicit `bootstrap` catch that starts from defaults,
shows one privacy-safe notice, and disables persistence for that process rather
than overwriting the unreadable file. Automatic repair/quarantine of that file
is out of scope.

v0.1.9 will add `PersistedSessionV2` and a `migrateV1ToV2` step. The public
migrator always returns `PersistedSessionCurrent`; adding v2 must not change
`fromPersistedSession` again.

### 5.3 Shell decomposition contract

`src/main.ts` remains the composition root. Extractions must:

- preserve Focus Mode DOM-preserving behavior, overlay exclusivity, and stable
  focus keys;
- keep controllers owning state transitions; extracted modules receive state +
  callbacks and must not import mutable globals from `main.ts`;
- avoid a framework migration; continue with the existing TypeScript + DOM
  approach;
- not change session-v1 field names as a side effect of moving code;
- keep `pnpm check` / existing Vitest suites green, and add unit tests for any
  pure helpers newly extracted from `main.ts`.

Locked extraction map (one commit per row, in order):

| New module | Move from `main.ts` | Boundary / test |
| --- | --- | --- |
| `src/app/quick-open-view.ts` | `renderQuickSwitcher*`, `bindQuickSwitcher*`, selection reconciliation, activation dispatch | Receives model/items/callbacks; ranking stays in `ui-logic.ts`; jsdom tests cover empty, indexing, partial, keyboard/click activation |
| `src/app/command-palette-view.ts` | `renderCommandPalette`, `bindCommandPalette`, input focus and focus trap | Receives `CommandPaletteController`; jsdom tests lock roles, disabled actions, selection, and focus |
| `src/app/workspace-view.ts` | tree/root/dialog/context-menu render and bind helpers, including root drag UI | Receives `WorkspaceController` plus callbacks; pure tree/focus helpers stay in `workspace.ts`/`accessibility.ts`; jsdom tests cover dialog focus, root removal confirmation, tree activation, and drag threshold/drop dispatch |
| `src/app/document-find-view.ts` | `renderDocumentSearch`, bind/refresh/move/activate/clear highlight helpers | Uses `search.ts` as source-match authority and the overlay model as state owner; jsdom tests cover ordinary/deferred code, no-match, wrap, and cleanup |

Settings and status-bar extraction is explicitly deferred unless the four rows
leave `main.ts` above 4,000 lines. The release gate is `main.ts <= 4,000` lines;
if necessary, move `renderSettings` and `renderStatusBar` into
`src/app/settings-view.ts` and `src/app/status-view.ts` without changing their
models. `main.ts` retains bootstrap, native event registration, controller
construction, `render`, `commit` synchronization, and cross-domain orchestration.

## 6. Implementation sequence

1. **IPC registry and exporter:** add pinned dependencies, `ipc.rs`, exporter,
   scripts, and generated bindings; keep behavior unchanged.
2. **IPC call-site migration:** replace all 26 raw invokes and remove only
   duplicate IPC DTOs; pass `pnpm ipc:check`, `pnpm build`, and Rust tests.
3. **Migration characterization:** add v1 fixtures against current behavior,
   then introduce `src/session/migrate.ts` and the Store-open failure boundary.
4. **Overlay UI extraction:** move Quick Open and Command Palette views with
   jsdom coverage.
5. **Workspace / Find UI extraction:** move the remaining two domains and meet
   the 4,000-line root limit.
6. **Release integration:** update `CHANGELOG.md`, `docs/ROADMAP.md`,
   `docs/RELEASING.md`, and `docs/releases/v0.1.8.md`; bump all version files
   with `pnpm release:prepare -- 0.1.8` only when cutting the release.

Each numbered item is independently reviewable and must leave `CI=true pnpm
check` green before the next begins.

## 7. Testing and QA

### Automated

- Frontend unit tests for every migration/default/normalization row in §5.2.
- `pnpm ipc:check` plus the generated call-site grep in §5.1.
- New jsdom view tests from §5.3 and all existing tests after moves.
- Rust tests for command-builder export and every DTO/error enum whose serde
  representation is nontrivial.
- Full gate: `CI=true pnpm check`.

### Manual

- Cold launch with an existing `markmaid-state.json` from v0.1.7 restores tabs,
  roots, scroll, theme, and external target preference.
- Corrupt the store version and confirm safe fallback without panic.
- Command Palette, Quick Open, Focus Mode, export, and external open smoke on
  Apple Silicon after shell extraction.
- VoiceOver smoke on Files tree, Quick Open, Command Palette, and document Find.

## 9. Risks and mitigations

| Risk | Mitigation |
| --- | --- |
| Pinned prerelease codegen stack stops compiling after another dependency update | Cargo.lock + exact Specta pins; fail the release and revise the plan rather than mixing generators |
| Large `main.ts` moves regress focus / overlays | Extract behind existing controllers; keep Focus Mode DOM-preserving tests |
| Migration harness accidentally changes defaults | Fixture equality against current production normalization before refactor |
| Scope creep into Favorites / i18n | Reject persistence field additions; only prepare seams |

## 10. Explicit deferrals to v0.1.9

- Favorites and Quick Open / Command Palette integration.
- Bookmarks, highlights, and notes sidecar metadata.
- Persisted reading positions beyond per-tab `scrollTop`, and bounded
  navigation / closed-tab history across restarts.
- Chinese / localized UI and a Settings language preference.
- Workspace Switcher and v0.2 discovery.
