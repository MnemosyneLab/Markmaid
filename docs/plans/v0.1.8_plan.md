# MarkMaid v0.1.8 Implementation Plan

## 1. Decision summary

v0.1.8 is an **engineering-foundation** release. It does not ship a new
user-facing reading workflow. Instead it hardens the seams that v0.1.9 and later
feature releases depend on:

1. a **typed frontend ↔ Rust command contract** so invoke payloads and results
   fail at generation or compile time when fields or tagged variants drift;
2. a **session migration test harness** that covers every persisted-session
   schema change, including the soft defaults used today; and
3. a continued **shell decomposition** of `src/main.ts` so the composition root
   stops owning Quick Open UI, Command Palette HTML, workspace tree chrome,
   Find highlighting, and bootstrap wiring.

v0.1.9 will consume these foundations for Favorites, reading history,
bookmarks / highlights / notes, and UI localization. Those features are
explicitly out of scope here.

Apple Developer ID signing and notarization remain outside this plan. The
existing Apple-Silicon, ad-hoc-signing release policy is unchanged.

## 2. Release outcomes

v0.1.8 is successful when:

- every Tauri command used by the frontend is described by a single typed
  contract; renamed fields, missing arguments, and mismatched tagged-result
  variants fail during type generation or TypeScript/Rust compilation rather
  than at runtime;
- loading and saving `markmaid-state.json` go through an explicit
  `migrateSession` pipeline with unit tests for invalid JSON, unknown versions,
  legacy `version: 1` fixtures, optional-field defaults, and forward-compatible
  ignored fields;
- `src/main.ts` is primarily a composition root (bootstrap, `commit`, native
  event wiring, and thin render orchestration) while Quick Open rendering,
  Command Palette rendering, workspace tree / dialog UI, document Find UI, and
  settings chrome live behind tested modules or controllers;
- all v0.1.7 preview, Command Palette, Focus Mode, external handoff, export,
  cancellation, accessibility, and session-v1 runtime behavior remains
  compatible; and
- README / changelog / roadmap updates describe the foundation theme without
  claiming new reading features.

## 3. Product boundary

### In scope

- Generate or otherwise maintain typed invoke bindings for every registered
  command in `src-tauri/src/lib.rs` `generate_handler![…]`.
- Align TypeScript argument and result types with Rust `Serialize` /
  `Deserialize` shapes (`camelCase`, tagged enums such as `TaskOutcome`).
- Introduce a pure session load path: parse → migrate → validate →
  `fromPersistedSession`, plus save-path serialization that always writes the
  current schema version.
- Add fixture-driven migration tests under the frontend (and Rust if any
  native session helpers appear) covering every field currently on
  `PersistedSessionV1` and every soft default.
- Extract remaining large UI domains from `main.ts` into `src/app/` (or sibling
  modules) without changing visual design or adopting a frontend framework.
- Keep session schema at a documented current version; if the typed contract or
  extraction requires renaming persistence helpers only, do not add Favorites /
  history / annotation fields yet (those land in v0.1.9 with a schema bump).

### Explicitly out of scope

- Favorites, bookmarks, highlights, notes, or persisted visit / closed-tab
  history (v0.1.9).
- UI language switching or string catalog localization (v0.1.9; this release may
  only make strings easier to find by extraction).
- Workspace Switcher, full-text search, backlinks, broken-link reports.
- Built-in editing, continuous filesystem watching, plugins, cloud sync.
- Performance optimizations that are not required to keep existing budgets /
  smoke checks green after the refactor.
- A frontend framework migration, cross-platform support, Developer ID signing,
  or notarization.
- Changing the public product behavior of Command Palette, Focus Mode, Quick
  Open ranking, or external-app handoff beyond equivalent refactors.

## 4. Current-state assessment

| Area | Current state | v0.1.8 implication |
| --- | --- | --- |
| IPC typing | Hand-written `invoke("name", args)` with optional generics; types in `src/types.ts` drift silently from Rust | Introduce a single source of truth and fail the build on drift |
| Specta / codegen | Not present in `package.json` / `Cargo.toml` | Adopt Tauri-compatible codegen (see §5.1) or an equivalent checked binding |
| Session schema | `PersistedSessionV1` with `version: 1`; `isPersistedSession` accepts only `version === 1`; soft defaults in `fromPersistedSession` | Keep `version: 1` as the stored schema unless a mechanical rename forces a bump; add an explicit migrator + tests |
| Legacy fields | `mermaidTheme?` typed but unread on restore | Document and test ignore / one-time normalize behavior inside the migrator |
| Runtime-only state | `focusMode`, `closedTabsHistory`, `documentVisitHistory` reset on load | Do not persist them in v0.1.8; migration tests assert they stay runtime-only |
| Shell size | `src/main.ts` ≈ 5.8k lines; controllers exist for preview, navigation, overlays, palette state, export, external apps, workspace tasks, persistence | Continue extraction: UI rendering and command wiring leave `main.ts` |
| Commands | `src/commands.ts` catalog already typed for palette IDs | Leave catalog behavior unchanged; only relocate wiring / HTML as needed |
| i18n | English string literals throughout TS and native menus | Do not localize yet; prefer extracting user-visible strings into named constants or modules to ease v0.1.9 |

## 5. Contracts to establish before implementation

### 5.1 Typed frontend ↔ Rust command contract

**Chosen approach:** generate TypeScript bindings from Rust command signatures
using a Tauri 2–compatible typed IPC toolchain (prefer `tauri-specta` +
`specta` if dependency and macOS CI cost stay acceptable; otherwise a checked
`ts-rs` / custom `build.rs` emitter that lists every `generate_handler`
command). Hand-maintained duplicate DTOs in `src/types.ts` for invoke payloads
must be deleted or become re-exports of generated types.

Rules:

- Every command in `generate_handler![…]` appears in the generated catalog.
  Adding a Rust command without regenerating bindings fails CI.
- Argument and result types use the same `camelCase` serde rename rules as
  today. Tagged enums such as `TaskOutcome` / cancellation results must be
  represented as discriminated unions in TypeScript.
- Frontend call sites use a thin wrapper (for example `api.reloadDocument(args)`)
  instead of raw string `invoke` names, except inside that wrapper.
- Privacy-sensitive fields (paths, filenames, document bodies) remain allowed in
  typed payloads where the product already sends them; the contract does not
  broaden what is logged or copied into diagnostics.
- Regenerated bindings are either committed or produced in `pnpm check` /
  `cargo test` before typecheck—pick one and document it in `docs/RELEASING.md`
  or the package scripts. Prefer committing generated output if CI runners are
  not guaranteed to run the emitter identically.

Acceptance:

- Rename a Rust result field in a throwaway branch and show that `pnpm check`
  (or the documented gate) fails before runtime.
- A smoke list of critical commands (`reload_document`,
  `index_workspace_markdown`, `list_external_open_targets`,
  `print_export_html`, `cancel_background_task`) has typed call sites and tests
  or compile-time usage.

### 5.2 Session migration harness

Add a pure module (suggested: `src/session/migrate.ts` or extend
`src/app/persistence.ts` with a separable pure core) that owns:

```text
parseSessionJson(raw) -> unknown | error
migrateSession(candidate, now) -> PersistedSessionCurrent | MigrationError
validateSession(session) -> PersistedSessionCurrent | ValidationError
```

Rules:

- `version` is mandatory and numeric. Unknown future versions fail closed to
  `DEFAULT_STATE` (same as today) and are covered by a test.
- Current stored schema remains `version: 1` for v0.1.8 unless a breaking field
  rename is unavoidable. The migrator still centralizes optional-field defaults
  that today live inline in `fromPersistedSession`.
- Every optional field on `PersistedSessionV1` has a fixture asserting the
  default applied when missing.
- Invalid tabs, negative scroll values, non-canonical recent paths, and invalid
  `externalOpenTargetId` values are normalized or dropped with deterministic
  rules already used in production—document those rules next to the tests.
- Save path always writes the current schema through `toPersistedSession` /
  equivalent; tests round-trip a full fixture.
- No production telemetry. Migration failures may surface through existing
  privacy-safe diagnostics counts only if already patterned; prefer silent
  fallback to defaults consistent with v0.1.7.

Minimum fixture set:

| Fixture | Expectation |
| --- | --- |
| Empty / non-object JSON | Defaults |
| `{ version: 2, … }` (future) | Defaults / rejected |
| Minimal v1 `{ version: 1, tabs: [], activeTabKey: null, theme: "system" }` | Valid; optional fields defaulted |
| Full v1 with every optional field | Round-trip equality on normalized form |
| Legacy `mermaidTheme` only | Ignored or normalized per documented rule; no crash |
| Corrupt tab entry | Dropped or repaired per rule |
| Oversized `recentDocuments` | Truncated to existing max (10) |

v0.1.9 will add `version: 2` (or additive v1 fields with an explicit migration
step). The harness must make that bump a mechanical addition of one migration
function and fixtures—not a rewrite of `fromPersistedSession`.

### 5.3 Shell decomposition contract

`src/main.ts` remains the composition root. Extractions must:

- preserve Focus Mode DOM-preserving behavior, overlay exclusivity, and stable
  focus keys;
- keep controllers owning state transitions; render helpers receive state +
  callbacks rather than importing mutable globals from `main.ts` where
  avoidable;
- avoid a framework migration; continue with the existing TypeScript + DOM
  approach;
- not change session-v1 field names as a side effect of moving code;
- keep `pnpm check` / existing Vitest suites green, and add unit tests for any
  pure helpers newly extracted from `main.ts`.

Recommended extraction order (may ship as multiple commits inside the release):

1. Quick Open render / bind / activate helpers → overlay or `quick-open-ui`
   module, leaving ranking in `ui-logic.ts`.
2. Command Palette HTML / event binding → beside
   `command-palette-controller.ts`, leaving catalog in `commands.ts`.
3. Workspace tree, root dialogs, and drag-reorder chrome → workspace UI module
   coordinating with `workspace-controller.ts`.
4. Document Find UI / match highlighting → find UI module beside overlay Find
   model.
5. Settings tab chrome and status-bar render helpers if they still bloat the
   root after the above.

Success metric: `main.ts` line count drops substantially (target: below ~3.5k
lines, or a documented equivalent reduction if shared helpers move without a
hard line quota), and new domain tests exist for the riskiest pure helpers.

## 6. Implementation sequence

1. Inventory all `invoke(` call sites and Rust `#[tauri::command]` entries;
   choose and wire the codegen toolchain.
2. Replace call sites with typed wrappers; delete duplicate hand types.
3. Extract `migrateSession` / validation from `state.ts` /
   `fromPersistedSession`; add fixtures before further refactors.
4. Extract Quick Open and Command Palette UI modules.
5. Extract workspace tree / Find UI modules; re-run accessibility keyboard
   smoke expectations against the same contracts as v0.1.6/v0.1.7.
6. Update docs: `CHANGELOG.md`, `docs/ROADMAP.md`, this plan’s checklist status,
   and a short `docs/releases/v0.1.8.md` draft when implementation completes.

## 7. Testing and QA

### Automated

- Frontend unit tests for migration fixtures listed in §5.2.
- Typecheck / generated-binding gate as part of `pnpm check`.
- Existing controller and command-palette tests remain green after moves.
- Rust unit tests only where new shared DTO helpers are introduced.

### Manual

- Cold launch with an existing `markmaid-state.json` from v0.1.7 restores tabs,
  roots, scroll, theme, and external target preference.
- Corrupt the store version and confirm safe fallback without panic.
- Command Palette, Quick Open, Focus Mode, export, and external open smoke on
  Apple Silicon after shell extraction.
- VoiceOver smoke on Files tree and palette if DOM structure changes.

## 8. Documentation deliverables

- [`docs/ROADMAP.md`](../ROADMAP.md) — mark v0.1.8 foundation items selected;
  point Favorites / history / annotations / i18n at v0.1.9.
- `CHANGELOG.md` — Unreleased / 0.1.8 engineering notes (no false feature
  claims).
- `docs/releases/v0.1.8.md` and checklist when cutting the release.
- Brief note in `docs/RELEASING.md` on regenerating IPC bindings if applicable.

## 9. Risks and mitigations

| Risk | Mitigation |
| --- | --- |
| Codegen toolchain fights Tauri 2 / macOS CI | Spike early; fall back to committed `ts-rs` or a custom emitter |
| Large `main.ts` moves regress focus / overlays | Extract behind existing controllers; keep Focus Mode DOM-preserving tests |
| Migration harness accidentally changes defaults | Fixture equality against current production normalization before refactor |
| Scope creep into Favorites / i18n | Reject persistence field additions; only prepare seams |

## 10. Explicit deferrals to v0.1.9

- Favorites and Quick Open / Command Palette integration.
- Bookmarks, highlights, and notes sidecar metadata.
- Persisted reading positions beyond per-tab `scrollTop`, and bounded
  navigation / closed-tab history across restarts.
- Chinese / localized UI and a Settings language preference.
- Workspace Switcher and v0.2 discovery.
