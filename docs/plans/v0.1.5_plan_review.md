# v0.1.5 Plan Review

Review of `docs/plans/v0.1.5_plan.md` against the current codebase.

## Overall verdict

The direction and scope are reasonable: reliability, large-folder performance,
security hardening, and doc consistency are sensible next steps after v0.1.4,
and the Out-of-Scope list is appropriately restrained. Most technical judgments
match the code (the dual-history model, UI freezes, stale Download docs, and the
print-window gap were all confirmed). Four points need correction or
clarification to avoid pitfalls or rework.

## Issues to fix

### 1. "Revoke asset-protocol grants when tabs close" is not feasible today

- Current state: `authorize_assets` (`src-tauri/src/document.rs:694`) only calls
  `asset_protocol_scope().allow_file()`. Tauri 2.11.5's `PathScope` exposes only
  `allow_file` / `allow_directory` — there is **no revoke API** (the scope only
  grows and cannot be shrunk within a session).
- Recommendation: instead authorize images only under the document's directory
  or pinned workspace roots (directory-level grants that persist for the
  session) — the only approach the current API supports that also narrows the
  authorization surface. If per-tab revocation is truly required, it needs a
  custom protocol / command with live authorization, which is much larger and
  better deferred.
- Related: `resolve_image` (`src-tauri/src/document.rs:1312`) canonicalizes and
  grants arbitrary absolute `file://` paths with no constraint to the document
  directory or pinned roots. Tightening this is the core of the security item;
  the plan should state "reject `file://` outside the document directory /
  roots" explicitly and cover it with a Rust test.

### 2. `.git` is already handled; the real gap is non-dotfile noise like `node_modules`

- All three walks — `directory_contains_visible_item` (`workspace.rs:923`),
  `list_workspace_children_inner`, and `collect_markdown_entries_inner`
  (`workspace.rs:681`) — skip entries starting with `.`, so `.git` is already
  covered. The new work is an explicit noise-directory skip list
  (`node_modules`, `dist`, `build`, `.venv`, `Pods`, `target`, …), and a
  decision on whether such directories (and any Markdown inside them) disappear
  from the Files tree entirely.
- `directory_contains_visible_item` is a full recursive walk with no cache or
  cap (`list_workspace_children` is a sync command that triggers one full
  subtree walk per directory entry) — the freeze is real. Recommendation: noise
  skip + per-directory memo/cache. Note that a pure depth cap can change the
  "hide empty directories" behavior, so treat it as a tunable constant or avoid
  it.
- Quick Open caps should be concrete (e.g. max entries 10k, max depth 12),
  keeping the existing stale-response rejection (already present since v0.1.3).

### 3. Unifying `.mmd` / image open is more than routing

- Current state: `load_workspace_mermaid` / `load_workspace_image` require a
  registered workspace root (`resolve_root`); the frontend errors with "Open
  Mermaid files from a pinned workspace folder." for paths outside a root
  (`src/main.ts:774-787`, `817-831`). argv / second-instance (`lib.rs:404`,
  `478`) and drag-drop (`main.ts:475`) filter to Markdown only and silently drop
  non-Markdown files.
- Unification requires generalizing those two Rust commands to accept absolute
  paths (mirroring `load_documents`) and dispatching by `classify_file`; also
  decide what happens to dropped files that are not md/mmd/images (silently
  ignore vs. a status-bar notice).
- This affects the security scope: the tightened image authorization must also
  cover this new open path.

### 4. Locate the actual "stuck at loading" gap

- The Markdown open/reload paths (`openDocumentPaths` `main.ts:469`,
  `reloadActiveDocument` `main.ts:559`, and the document branch of
  `ensurePreviewLoaded` `main.ts:738`) have no try/catch around `invoke`, so a
  rejection leaves the tab stuck at `status: "loading"`. The Mermaid/image paths
  already catch and produce error tabs.
- Recommendation: one shared "invoke rejection → error tab / status-bar notice"
  helper; a failed open becomes an error tab, a failed reload keeps the previous
  preview for ready documents (existing behavior) and becomes an error tab for
  loading documents.

## Confirmed points

- Dual history model is real: per-tab `history` / `historyIndex` (written by
  `navigateDocument` at `state.ts:644`) is written but never read; the Back /
  Forward buttons and menu shortcuts use only the global `documentVisitHistory`
  (`main.ts:2201`, `computeNavigationControlState`). `state.test.ts` covers the
  per-tab model, so collapsing must update those tests — the plan already
  mentions tests, correct.
- Stale Download docs are real: `README.md:14`, `CHANGELOG.md:75`,
  `docs/examples/gfm-and-code.md:4` still claim code-block download; the code
  only keeps Export SVG in the diagram viewer.
- Print window: a 10-minute frontend cleanup timer (`src/print.ts:10`) and a 15s
  asset wait already exist; the real gap is a Rust-side watchdog for a hidden
  window whose page never loads, plus the overly long 10-minute timer.
  Narrowing capabilities is feasible (`print-export-*` currently inherits the
  full `default` capability — dialog/opener/store/window-state, see
  `src-tauri/capabilities/default.json`).

## To add / clarify

- Test feasibility: `authorize_assets` depends on `&AppHandle`, so unit tests
  should follow the workspace `_inner` pattern to extract pure logic; `main.ts`
  orchestration is hard to test directly, so put "invoke rejection → error tab"
  into a testable reducer.
- Delivery order: Security is small and low-risk; consider moving it before
  Performance.
- Rust tests to add: `classify_file` dispatch, `resolve_image` `file://`
  out-of-bounds rejection, noise-directory skipping, tightened image
  authorization.
- Frontend tests to add: unified open dispatch (md/mmd/image), invoke-rejection
  → error tab, single-history collapse.
