# MarkMaid v0.1.6 Implementation Plan

## 1. Decision summary

v0.1.6 is a focused workspace-polish and maintainability release following the
published v0.1.5 hardening release. It implements only the five items selected
as the roadmap's recommended first cut:

1. reorder pinned workspace folders;
2. copy a privacy-safe diagnostic report;
3. cooperatively cancel superseded native work;
4. split the frontend shell into explicit domain controllers; and
5. complete an accessibility and keyboard-navigation pass.

The release must not become a bundle of unrelated reader features. Command
Palette, Workspace Switcher, Favorites, Focus Mode, Open in External Editor,
full-text search, backlinks, and persistent reading history remain future
candidates.

This plan intentionally excludes Apple Developer ID signing and notarization.
The existing ad-hoc signing and quarantine instructions remain unchanged.

## 2. Release outcomes

v0.1.6 is successful when:

- pinned roots can be reordered with a drag handle and with non-drag context
  actions, and the order survives restart;
- Quick Open uses pinned-root order only as a deterministic tie-breaker without
  changing its existing relevance/source priority;
- Settings can copy a deterministic diagnostic report that contains useful
  environment and state counts but no document content, filenames, or full
  paths;
- closing, retrying, refreshing, or superseding eligible work requests a native
  cancellation, while stale-result guards remain authoritative;
- `src/main.ts` is a composition root rather than the owner of every workspace,
  preview, navigation, overlay, export, and persistence implementation detail;
- the Files tree, tabs, context menus, dialogs, viewers, notices, and resize
  controls have documented keyboard/focus behavior and pass a VoiceOver smoke
  test; and
- all v0.1.5 opening, navigation, export, print, workspace, and asset-boundary
  behavior remains compatible.

## 3. Product boundary

### In scope

- Reorder registered workspace roots in app state only.
- Preserve root identity, expansion state, cached children, open tabs, and disk
  contents during reorder.
- Add a Settings diagnostics section and Copy Diagnostics action.
- Add in-memory cancellation tokens for preview loads/reloads/theme rerenders,
  Quick Open indexing, and workspace child listing.
- Extract existing frontend domains behind small, testable interfaces without
  changing visual design or adopting a framework.
- Add missing WAI-ARIA keyboard, focus, live-region, and reduced-motion behavior.
- Add tests and fixture-driven performance checks for the changed contracts.

### Explicitly out of scope

- Reordering files or folders on disk.
- Persisted named workspaces or workspace switching.
- A Command Palette or new global shortcut surface.
- Favorites, bookmarks, annotations, or persisted visit history.
- Full-text body search, backlinks, or broken-link indexing.
- Continuous filesystem watching or background indexing.
- Markdown editing, saving, autosave, or conflict resolution.
- Immediate preemption of Comrak or Merman while inside one non-interruptible
  render call.
- A new frontend framework, state-management library, or visual redesign.
- Telemetry, automatic diagnostic upload, crash reporting, or analytics.
- Cross-platform work, Developer ID signing, or notarization.

## 4. Current-state assessment

| Area | Current state | v0.1.6 implication |
| --- | --- | --- |
| Root order | `workspaceRoots` is already an ordered array and is persisted in session v1; the Rust registry is identity-based | Reordering needs frontend state/UI work only; no persistence migration or Rust mutation command |
| Files tree | Every visible node currently receives `tabindex="0"`; Up/Down/Home/End tree navigation is missing | Introduce roving tabindex and complete tree keyboard semantics before calling drag reorder accessible |
| Root actions | Workspace context menus support root removal but not position changes | Add Move Up/Move Down as the required non-drag alternative |
| Quick Open | Workspace index requests reject stale results, but backend entries are sorted independently of pinned order | Preserve relevance ranking and add root position as a final workspace-result tie-breaker |
| Preview work | `PreviewRequestTracker` invalidates stale frontend completions | Retain it; cancellation is a performance optimization, not a replacement |
| Native work | Preview loading, folder listing, and indexing use `spawn_blocking` but run to completion | Add cooperative flags and checkpoints around bounded units of work |
| Diagnostics | `copyText` already provides Clipboard API plus WebView fallback; Settings has no diagnostic section | Reuse the copy seam and generate a redacted report on demand |
| Frontend shell | `src/main.ts` owns bootstrap, mutable UI models, rendering, event binding, workspace, preview, navigation, overlays, and persistence | Introduce a small runtime/store contract and extract one domain per behavior-preserving commit |
| Accessibility | Some roles, focus traps, reduced-motion CSS, and keyboard handlers exist; behavior is inconsistent | Consolidate utilities and verify semantics rather than replacing the UI |

## 5. Contracts to establish before implementation

### 5.1 Pinned-root ordering contract

Add a pure root-order operation with this behavior:

```text
moveWorkspaceRoot(roots, rootId, targetIndex) -> roots
```

- Unknown `rootId` returns the original array unchanged.
- `targetIndex` is clamped to the valid range.
- Moving to the current index returns the original array reference.
- The operation preserves every `WorkspaceRoot` object and changes only order.
- Canonical-path deduplication remains unchanged.
- Expansion state is keyed by root ID and must not be rewritten.
- Child caches are keyed by root ID/path and must not be invalidated.
- Open preview tabs, recents, selected tree nodes, and document history are not
  changed.
- Reorder is persisted through the existing `workspaceRoots` session-v1 field;
  do not bump the persisted-session schema.

The UI contract is:

- show a drag handle only on root rows, not on nested folders/files;
- start dragging only after the existing tab-style movement threshold so a
  click or disclosure-button action is never mistaken for a drag;
- show a clear insertion position and retain the dragged root's selection;
- add Move Up and Move Down to the root context menu, disabling the unavailable
  boundary action;
- after a successful pointer or menu move, place focus back on the moved root
  and announce its new 1-based position through a dedicated polite live region;
- do not add a global keyboard shortcut in v0.1.6.

Quick Open keeps the current ordering model:

1. open tabs;
2. workspace matches;
3. recent documents;
4. existing match-quality rules inside each source; and
5. pinned-root order only as a tie-breaker between equally ranked workspace
   matches, followed by the existing deterministic path comparison.

When nested roots contain the same canonical Markdown path, the first pinned
root owns the deduplicated index entry on the next explicit Quick Open refresh.
Reordering may therefore change the displayed root label, but never the opened
canonical path.

### 5.2 Diagnostics and privacy contract

Add a Diagnostics section near the bottom of Settings with one primary action:
**Copy Diagnostics**. Do not add a menu item or shortcut in this version.

The copied plain-text format is versioned and deterministic:

```text
MarkMaid diagnostics v1
App: MarkMaid 0.1.6
Runtime: macOS <version-or-unavailable> (aarch64)
Build: <debug-or-release>
Tabs: total=<n>, document=<n>, mermaid=<n>, image=<n>, error=<n>, loading=<n>
Workspace: roots=<n>, expanded-nodes=<n>
Quick Open: <idle|indexing|ready|failed>, unavailable-roots=<n>, truncated-roots=<n>
UI: appearance=<system|light|dark>, resolved=<light|dark>, palette=<name>, tabs=<top|left>
Recent error: operation=<redacted-operation-or-none>, code=<normalized-code-or-none>
```

Rules:

- Obtain app version/build mode/OS/architecture from a small read-only Rust
  diagnostics command where possible.
- Prefer a system API for the exact macOS version. Do not shell out to an
  arbitrary command or add a broad capability. If an exact version would
  require disproportionate dependency work, return `unavailable` while still
  reporting `macOS` and `aarch64`.
- Merge the Rust environment data with frontend state counts in
  `src/diagnostics.ts`.
- Never include source Markdown, rendered HTML/SVG, image URLs, filenames,
  display names, canonical/requested paths, recent-document entries, search
  queries, clipboard content, or raw backend error messages.
- Keep only the latest diagnostic event's operation and normalized error code
  in memory. Do not persist it.
- Report copy success/failure through the existing status-notice pattern and an
  `aria-live` announcement.
- Never transmit diagnostics; copying is the only output action.

### 5.3 Cooperative cancellation contract

Correctness continues to rely on frontend request generation checks. Native
cancellation only reduces wasted work and must be safe when it loses a race.

Introduce an in-memory Rust `BackgroundTaskRegistry`:

```text
task_id -> Arc<AtomicBool cancelled>
```

- Task IDs are opaque, process-local strings generated by the frontend.
- Registration happens before entering `spawn_blocking`.
- `cancel_background_task(taskId)` sets the flag if registered and otherwise is
  a harmless no-op.
- A guard removes the registry entry on success, cancellation, error, or panic
  unwind.
- IDs and cancellation state are never persisted.
- Reusing an active task ID is rejected in tests and avoided by construction.

Use explicitly tagged command outcomes so cancellation is not rendered as an
error:

```text
completed -> existing typed payload
cancelled -> no payload, no user-facing error
```

Eligible commands:

- `load_preview_paths` — cancellation can be checked between batch items and at
  safe checkpoints inside document/Mermaid/image loading;
- `reload_document` — one task ID per reload;
- `index_workspace_markdown` — check for every directory and file iteration;
- `list_workspace_children` — check during the bounded descendant-visibility
  scan as well as before returning children.

Frontend cancellation triggers:

- closing or retrying a loading preview;
- replacing a lazy-load/reload request for the same tab;
- superseding a Mermaid theme rerender batch;
- closing Quick Open, invalidating its index, or starting a newer index request;
- collapsing/removing a root whose uncached child listing is still running.

For a multi-path open, keep per-tab stale-result tokens. Give each batch item a
task ID so closing one tab can skip that pending item without cancelling useful
siblings. A cancellation arriving before native registration or during one
Comrak/Merman call may not stop that call; its result is still discarded by the
existing generation check. Do not claim hard thread interruption.

Change the preview batch payload/result shape explicitly:

```text
PreviewTaskRequest { taskId, path }
PreviewTaskOutcome { taskId, status: completed, result }
PreviewTaskOutcome { taskId, status: cancelled }
```

Preserve result order by request order, including cancelled placeholders, so a
partial batch can never be applied to the wrong loading tab.

Cancellation checkpoints must occur:

- before filesystem metadata/read operations;
- after a file read and before parsing/rendering;
- before local asset authorization;
- between preview batch items;
- at each workspace directory/file iteration; and
- before publishing the final command result.

### 5.4 Frontend runtime and controller contract

Keep `src/main.ts` as the composition root. Do not introduce a reactive
framework. Add one small runtime interface shared by controllers:

```text
getState() -> AppState
commit(nextState, { render, persist })
showNotice(kind, message)
```

Platform effects such as Tauri `invoke`, file dialogs, reveal/open, clipboard,
timers, and native listeners must be passed as explicit dependencies or kept in
the composition root. Controllers must not import mutable values from
`main.ts`.

Target module ownership:

| Module | Responsibility |
| --- | --- |
| `src/app/runtime.ts` | State access/commit contract, render/persist scheduling hooks |
| `src/app/preview-controller.ts` | Open, lazy load, reload, theme rerender, preview task lifecycle |
| `src/app/workspace-controller.ts` | Root restore/add/remove/reorder, child cache, tree actions, index invalidation |
| `src/app/navigation-controller.ts` | Tab selection/closure/reopen and global document visit navigation |
| `src/app/overlay-controller.ts` | Quick Open, Find, and generic modal/context-menu focus lifecycle; domain controllers provide content/actions |
| `src/app/export-controller.ts` | Export modal state/wiring while `export.ts` keeps export generation/orchestration |
| `src/app/persistence.ts` | Store bootstrap, session write scheduling, native recent/closed-tab sync |
| `src/diagnostics.ts` | Redacted report model/formatting and Copy Diagnostics orchestration |
| `src/accessibility.ts` | Roving focus, focus trap/restore, menu keys, live announcements |
| `src/main.ts` | Bootstrap, dependency composition, native listener registration, top-level shell render |

Existing pure modules (`state.ts`, `workspace.ts`, `ui-logic.ts`, `search.ts`,
`status.ts`, `freshness.ts`, `export.ts`) remain pure or narrowly effectful. Do
not move code merely to hit a line-count target; move complete ownership and its
tests.

Refactor-only commits must not alter markup, shortcuts, persistence, error copy,
or async ordering. Each extracted domain must pass the full quality gate before
the next extraction.

### 5.5 Accessibility and focus contract

Use a dedicated visually hidden live region for short application status. The
entire content stage must not be `aria-live`, because rendering a document
should not cause VoiceOver to announce its full content again.

Required behavior:

- Files tree uses roving tabindex: exactly one visible treeitem has `tabindex=0`.
- Up/Down move to previous/next visible item; Home/End move to boundaries;
  Right expands or enters the first child; Left collapses or moves to the
  parent; Enter performs the existing activation.
- Tab lists expose correct `tablist`/`tab` semantics, orientation, selected
  state, roving tabindex, and Arrow/Home/End movement without breaking
  `Ctrl+Tab`.
- Sidebar view tabs implement keyboard movement and reference their tab panels.
- Tab and workspace context menus use `menu`/`menuitem`, focus the first enabled
  item, support Up/Down/Home/End, close on Escape, and return focus to the
  invoking control.
- Quick Open, workspace dialogs, export modal, and diagram/image viewer trap
  focus, close on Escape where safe, and restore focus to the opener.
- Closing/reordering a focused root or tab moves focus to a deterministic
  surviving neighbor.
- Sidebar resize remains operable with arrow keys and exposes current/min/max
  values through separator ARIA attributes.
- Drag-only affordances always have a keyboard/menu alternative.
- Existing reduced-motion and reduced-transparency behavior is retained and
  manually verified in overlays, viewer zoom/pan, tab/root drag, and anchor
  navigation.

## 6. Workstreams

### Workstream A — Characterization tests and runtime seam

1. Add tests for current root persistence/order, Quick Open ranking, preview
   stale-result behavior, workspace cache identity, focus restoration, and
   overlay close semantics before moving code.
2. Add `AppRuntime` and a test fake without changing app behavior.
3. Route state replacement, render, persistence scheduling, and notices through
   the runtime seam.
4. Keep bootstrap and current top-level render in `main.ts` until every caller
   has migrated.
5. Run `CI=true pnpm check`; land this as a refactor-only change.

### Workstream B — Workspace controller and root reorder

1. Add `moveWorkspaceRoot` and root-order lookup helpers to `workspace.ts`.
2. Extend Quick Open ranking with the root-order tie-breaker.
3. Extract root restore/add/remove, child cache, tree activation, mutation
   dialog/action state, context-menu actions, and index invalidation into
   `workspace-controller.ts`; use generic overlay focus/menu primitives rather
   than duplicating them.
4. Add a root drag handle and reuse the proven tab drag threshold/click
   suppression pattern without sharing mutable drag sessions.
5. Add insertion styling and edge auto-scroll only if the sidebar can actually
   overflow during a fixture test; otherwise defer auto-scroll.
6. Add Move Up/Move Down context actions with correct disabled boundaries.
7. Commit reordered state through the existing session-v1 persistence path.
8. Restore selection/focus and announce the new position.
9. Confirm no Rust workspace command, cache invalidation, filesystem mutation,
   or schema migration is introduced.

### Workstream C — Privacy-safe Copy Diagnostics

1. Add `src-tauri/src/diagnostics.rs` with a serializable environment result and
   a read-only `get_diagnostics_environment` command.
2. Register the command without widening print-window or filesystem
   capabilities.
3. Add `src/diagnostics.ts` with a pure snapshot builder, redaction rules, and
   deterministic formatter.
4. Normalize error events at existing catch boundaries into a bounded
   operation/code-only in-memory record.
5. Add the Settings Diagnostics section and Copy Diagnostics button.
6. Reuse `copyText`; report success/failure without replacing the current tab or
   persisting report contents.
7. Add an adversarial privacy test containing paths, filenames, source, raw
   error messages, and search queries, and assert none appear in the report.

### Workstream D — Preview/index controllers and cooperative cancellation

1. Add `src-tauri/src/tasks.rs` with the registry, token, cleanup guard, and
   `cancel_background_task` command.
2. Define tagged completed/cancelled response types in Rust and TypeScript.
3. Thread cancellation tokens through preview batch items, reload, workspace
   indexing, and child visibility scanning.
4. Add checkpoints without changing the current extension, symlink, file-size,
   asset-authorization, depth, or entry-limit policy.
5. Extend `PreviewRequestTracker` or replace it with a domain-neutral frontend
   task tracker that owns both generation tokens and native task IDs.
6. Extract preview lifecycle code into `preview-controller.ts` and Quick Open
   task lifecycle into `overlay-controller.ts`.
7. Add a `pendingWorkspaceChildren` map keyed by root/relative path so duplicate
   callers share one native task; collapse/remove cancels and removes the entry.
8. Send best-effort cancel commands on every trigger listed in section 5.3.
9. Treat `cancelled` as silent state cleanup. A still-current user-requested tab
   must never become an error tab solely because an earlier task was cancelled.
10. Prove registry entries are removed after success, error, cancellation, and
   a simulated join failure.

### Workstream E — Remaining shell extraction

1. Extract tab/document navigation into `navigation-controller.ts` while keeping
   `state.ts` reducers as the source of truth.
2. Consolidate generic overlay open/close/focus lifecycle in
   `overlay-controller.ts`; workspace and export controllers retain their domain
   actions and models.
3. Move state-store debounce and native recent/reopen synchronization into
   `persistence.ts`.
4. Keep `export.ts` as the export implementation; move only modal/shell wiring
   into `export-controller.ts`.
5. Remove duplicate global sequences/sets only after their owning controller has
   an equivalent tested lifecycle.
6. Check the dependency graph for cycles. Controllers may depend on pure helpers
   and the runtime interface, not on each other's internal mutable state.
7. Run the full gate after every domain extraction, not only at the end.

### Workstream F — Accessibility pass

1. Add reusable roving-focus, menu-key, focus-trap, focus-restore, and live-region
   helpers in `accessibility.ts`.
2. Apply the complete keyboard contracts from section 5.5 to Files, tabs,
   sidebar views, context menus, dialogs, Quick Open, export, and viewers.
3. Replace broad content-stage live announcements with the dedicated live
   region.
4. Preserve focus across the full-shell rerender by storing a stable focus key
   and restoring only when the corresponding control still exists.
5. Ensure root reorder and tab reorder have non-drag alternatives and audible
   completion messages.
6. Verify visible focus indicators in every color theme and in high contrast.
7. Verify 200% zoom, reduced motion, reduced transparency, and keyboard-only
   use without clipped critical controls.
8. Perform a VoiceOver smoke pass using the manual matrix below.

### Workstream G — Documentation and release preparation

1. Update README features/shortcuts only for shipped v0.1.6 behavior.
2. Add a dated v0.1.6 changelog section with diagnostics privacy and cooperative
   cancellation limitations stated accurately.
3. Update `docs/ROADMAP.md`: mark promoted items complete and retain deferred
   candidates.
4. Add `docs/releases/v0.1.6.md` and
   `docs/releases/v0.1.6-checklist.md` using the established release format.
5. Document that cancellation is cooperative, no telemetry exists, and Apple
   signing/notarization remains out of scope.

## 7. Test plan

### Frontend unit tests

- root move: first/middle/last, unknown ID, clamped index, no-op identity,
  duplicate canonical path protection, and session round trip;
- Quick Open root-order tie-breaker without changing tab/workspace/recent source
  priority or match-quality ranking;
- root reorder preserves expansion maps, selected root ID, caches, tabs, recents,
  and history;
- diagnostics formatting is deterministic and rejects every prohibited field;
- diagnostics counts every tab kind/status and handles unavailable environment
  fields;
- task tracker start/supersede/cancel/finish races and silent cancelled outcomes;
- controller behavior with fake runtime/invoke dependencies;
- tree/tab/menu keyboard action reducers, roving tabindex, focus fallback, and
  focus restoration;
- status live-region messages and reduced-motion selection logic;
- persisted-session v1 compatibility with pre-v0.1.6 data.

### Rust unit tests

- diagnostics environment serialization, unavailable OS-version fallback, and
  absence of paths/content;
- task registration, duplicate ID rejection, unknown cancel no-op, cancellation
  visibility across threads, and guard cleanup;
- preview batch skips a cancelled pending item without dropping completed
  siblings;
- cancellation before read, before render, before asset authorization, and
  before final result;
- index and visibility scans stop at a cancellation checkpoint and do not report
  the result as unavailable/truncated;
- existing symlink, size, path-boundary, noise-directory, depth, and entry-cap
  tests continue to pass with cancellation tokens;
- command response serialization matches the tagged TypeScript contract.

### Integration and regression tests

- rapidly open/close/retry Markdown, Mermaid, and image tabs and confirm no stale
  or cancelled completion changes active state;
- change Mermaid theme repeatedly and confirm only the final theme appears;
- open/close Quick Open repeatedly on a large fixture and confirm old indexes do
  not surface or become errors;
- collapse/remove a root during child loading and confirm no stale children or
  notices appear;
- reorder roots, restart, and confirm visual order, expansion, selection fallback,
  and Quick Open tie-breaks;
- copy diagnostics after representative preview/workspace/export failures and
  inspect for forbidden data;
- exercise all existing v0.1.5 open, history, reload, export, print, and local
  image authorization paths after controller extraction.

### Quality gates

- `CI=true pnpm check` passes TypeScript, Vitest, Vite, Rust tests, rustfmt, and
  Clippy.
- `CI=true pnpm tauri build --debug --bundles app --target
  aarch64-apple-darwin` produces the debug app.
- `git diff --check` passes.
- Version metadata, changelog links, README, roadmap, release notes, and release
  checklist agree before tagging.

## 8. Manual QA matrix

### Root reorder

1. Reorder 1, 2, and 10+ roots by drag handle and context actions.
2. Verify first/last Move actions are disabled correctly.
3. Click, expand, double-click, right-click, and drag near the threshold to
   confirm ordinary tree interaction never begins an accidental reorder.
4. Restart and verify order/expansion; remove/re-add a root and verify no stale
   position or cache remains.
5. Use VoiceOver and keyboard-only context actions; confirm position
   announcements and focus restoration.

### Diagnostics

1. Copy from Settings in normal, loading, and representative error states.
2. Paste into a plain-text editor and verify formatting, version, architecture,
   counts, and normalized error code.
3. Confirm no source text, filenames, paths, recent entries, queries, SVG/HTML,
   or raw error messages appear.
4. Deny/fail clipboard access and confirm a useful non-destructive notice.

### Cancellation and regressions

1. Use large Markdown/Mermaid/workspace fixtures to make work observable, then
   close, retry, supersede, collapse, or dismiss it.
2. Confirm cancellation never produces an error tab/notice and no registry job
   remains after completion.
3. Confirm a long single render may finish internally but never applies stale
   UI state.
4. Repeat multi-select Open and close one pending tab; useful sibling results
   must still load.

### Accessibility

1. Traverse the whole app using keyboard only: title actions, tabs, sidebar
   switch, Files tree, context menus, dialogs, Settings, viewers, and export.
2. Verify tree Arrow/Home/End/Enter behavior and one-tab-stop roving focus.
3. Verify every modal traps focus, Escape behavior is safe, and focus returns to
   its opener or deterministic neighbor.
4. With VoiceOver, confirm roles/names/state for tabs, treeitems, menus, status
   notices, loading/error states, and reordered positions.
5. Verify high-contrast palettes, 200% zoom, reduced motion, and reduced
   transparency.
6. Re-run native PDF print success/cancel/cleanup because focus/live-region and
   controller refactors touch the app shell.

## 9. Performance and resource rules

- Root reorder is an `O(n)` in-memory array operation and must not call Rust,
  traverse the filesystem, reload previews, or refresh Quick Open immediately.
- Diagnostics generation is `O(tabs + roots + expanded paths)` and must not read
  document files or traverse workspace directories.
- Cancellation checks add constant work per existing file/directory iteration;
  do not add a polling thread per task.
- At most one registry entry exists per active task ID, and every terminal path
  removes it.
- Do not add a disk cache, persistent index, background watcher, or new
  concurrency scheduler in v0.1.6.
- Keep current 16 MiB text, 100 MiB image, visibility scan, index depth/entry,
  Quick Open display, and print timeout limits unchanged unless a measured
  regression requires a separately reviewed adjustment.

## 10. Migration and rollback

- Persisted session remains version 1; root order is already represented by the
  existing array order.
- Diagnostics and task state are process-local and require no cleanup migration.
- If v0.1.6 code is rolled back, v0.1.5 reads the same session data and simply
  ignores the newer runtime-only behavior.
- Refactor commits must remain separable from behavior commits so a controller
  extraction can be reverted without removing a completed user feature.
- No release step changes, certificate work, or capability broadening is
  required.

## 11. Risk register

| Risk | Mitigation |
| --- | --- |
| Root drag breaks expand/select like earlier tab drag regressions | Dedicated handle, movement threshold, deferred pointer capture, context-action fallback, click/drag regression tests |
| Full-shell rerender loses focus | Stable focus keys, deterministic fallback, focus tests, domain extraction that reduces unnecessary global renders |
| Cancellation is mistaken for correctness | Keep generation/stale checks authoritative and document non-interruptible render limits |
| Cancellation registry leaks IDs | RAII cleanup guard and tests for every terminal path |
| Batch cancellation drops useful sibling previews | Per-item task IDs and tagged outcomes |
| Diagnostics leaks private paths/content | Allowlist fields, pure formatter, adversarial redaction tests, no raw error messages |
| Shell refactor changes behavior invisibly | Characterization tests first, one domain per commit, full gate after every extraction |
| Accessibility changes shortcuts unexpectedly | Preserve existing shortcuts, implement standard local widget keys only, manual keyboard/VoiceOver matrix |
| Scope expands into roadmap extras | Treat sections 2 and 3 as the release contract; move extras to a later plan |

## 12. Delivery order

Implement as small, reviewable commits in this order:

1. characterization tests and runtime seam;
2. workspace controller extraction without behavior changes;
3. root reorder state, UI, persistence, and Quick Open tie-breaker;
4. diagnostics Rust command, formatter, Settings UI, and privacy tests;
5. task registry and tagged cancellation contracts;
6. preview/index controller extraction and cancellation wiring;
7. navigation, overlays, export shell, and persistence extraction;
8. accessibility utilities and widget-by-widget fixes;
9. full regression/manual matrix and docs/release preparation.

Do not combine steps 2, 5, or 7 with unrelated visual changes. If the shell
refactor reveals a product behavior question, stop and update this plan rather
than resolving it implicitly in code.

## 13. Definition of done

v0.1.6 is ready only when:

- [ ] all five selected roadmap items meet their contracts;
- [ ] no deferred roadmap feature has slipped into the release;
- [ ] session-v1 compatibility and read-only behavior are preserved;
- [ ] diagnostic privacy and cancellation cleanup tests pass;
- [ ] keyboard-only and VoiceOver manual matrices pass;
- [ ] existing v0.1.5 open/navigation/export/print/asset behavior passes;
- [ ] `CI=true pnpm check` and the arm64 debug app build pass;
- [ ] README, changelog, roadmap, public release notes, and signoff checklist are
  current; and
- [ ] the final clean commit is pushed before release artifacts, dry-run, tag,
  and GitHub Release publication.
