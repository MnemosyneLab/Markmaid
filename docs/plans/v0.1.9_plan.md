# MarkMaid v0.1.9 Implementation Plan

## 1. Decision summary

v0.1.9 is a **reading-continuity and localization** release. It builds on the
v0.1.8 engineering foundation (typed IPC, session migration harness, thinner
shell) and ships the user-facing metadata workflows selected for this line:

1. **Favorites** — pin frequently read documents independently of Recents,
   stored only as app metadata;
2. **Favorites in Quick Open and the Command Palette** — discovery and toggle
   without inventing a second search surface;
3. **Bookmarks / highlights / notes** — sidecar annotations that never write
   into Markdown source files, with Command Palette actions;
4. **Bounded persisted reading history** — restore navigation continuity across
   restarts beyond today’s per-tab `scrollTop`; and
5. **Chinese / localized UI** — extract strings and add a Settings preference
   for UI language with English fallback tests.

The release must preserve MarkMaid’s read-only boundary: annotations and
favorites never modify document bytes on disk. Full-text search, backlinks,
Workspace Switcher, and editing remain out of scope.

Apple Developer ID signing and notarization remain outside this plan.

## 2. Release outcomes

v0.1.9 is successful when:

- a user can favorite / unfavorite a ready document from the UI and Command
  Palette; favorites survive restart, stay capped, and never appear as edits to
  the Markdown file;
- Quick Open ranks or sections Favorites distinctly from tabs, workspace path
  matches, and Recents; Command Palette exposes add/remove and open-favorite
  commands without putting file paths into the static command catalog as
  command IDs;
- bookmarks, highlights, and notes are stored as app sidecar metadata keyed by
  stable path identity, degrade safely when the file changes or disappears, and
  are reachable from the Command Palette;
- document visit history and closed-tab reopen history both persist across
  restarts within their existing bounds; missing targets are removed only by an
  explicit user action after a failed open;
- the UI can be shown in English or Simplified Chinese via Settings, including
  Command Palette labels and primary shell chrome, with missing keys falling
  back to English in tests; and
- new controllers/views/catalogs do not grow `src/main.ts` past the existing
  4,000-line composition-root gate; and
- session migration from v0.1.8 / `version: 1` fixtures upgrades cleanly through
  the v0.1.8 migrator into the new schema version with fixture coverage; an
  unsupported future session version opens with defaults in read-only recovery
  mode and is never overwritten by this process.

## 3. Product boundary

### In scope

- Persist an ordered, capped Favorites list in session v2 using canonical paths
  only—no document bodies.
- Tab context menu and Command Palette affordances for Toggle Favorite. No new
  titlebar/sidebar button is added in v0.1.9.
- Extend Quick Open item kinds with `"favorite"` and use the exact tab →
  favorite → workspace → recent priority defined in §5.1.
- Sidecar models for:
  - **Bookmarks** — named positions with path + scrollTop and an available
    nearest-heading anchor;
  - **Highlights** — confirmed Find matches tied to UTF-16 source offsets,
    quote context, and SHA-256 source fingerprint;
  - **Notes** — short plain-text notes attached to a path or bookmark, stored
    only in app metadata.
- Command Palette commands listed exactly in §5.2; all dynamic annotation rows
  remain in the shared annotation overlay.
- Persist both bounded `documentVisitHistory` and `closedTabsHistory` across
  sessions; restore Back/Forward/Reopen continuity where targets remain valid.
- String catalog extraction for user-visible TypeScript UI strings and all
  MarkMaid-authored native menu labels; Settings control for the exact union
  `uiLocale: "system" | "en" | "zh-Hans"`.
- Schema bump via the v0.1.8 migration harness from version 1 to exactly version
  2.

### Explicitly out of scope

- Writing favorites, bookmarks, highlights, or notes into Markdown, HTML
  comments, front matter, or sibling `.md` files in the workspace.
- Syncing annotations via iCloud / git / third-party services.
- Full-text body search, backlinks, broken-link reports, or wikilinks.
- Workspace Switcher (named pinned-root sets)—still a later candidate.
- Built-in Markdown editing, continuous filesystem watching, or auto-reload
  beyond existing focus/tab Reload–Ignore behavior.
- Complete localization of every native error string from macOS APIs; privacy
  diagnostics remain code-based where already designed.
- Additional locales beyond English + Simplified Chinese in this release.
- Graph views, daily notes, or Obsidian-compatible vault formats.
- Developer ID signing, notarization, or cross-platform support.

## 4. Verified baseline and locked product decisions (2026-08-13)

| Area | Current state | v0.1.9 implication |
| --- | --- | --- |
| Recents | `recentDocuments: string[]` max 10, persisted | Favorites are a separate list; never conflate the two |
| Quick Open | kinds `tab` \| `workspace` \| `recent` in `ui-logic.ts` | Add `favorite`; keep path/name matching only |
| Command Palette | Static `CommandId` catalog in `commands.ts` | Add toggle/open commands; do not encode paths as command IDs |
| Scroll | Per-tab `scrollTop` already persists; runtime visit history is capped at 50 and closed-tab history at 20; current Reopen consumes the closed entry before the asynchronous open result is known | Persist the existing shapes and limits, but add transactional activation/removal semantics so a failed target is not consumed implicitly |
| Annotations | None | New sidecar store; never touch file bytes |
| Session | v0.1.8 migrator + `version: 1` | Bump the session to v2 for favorites, locale, and histories; keep annotations in their own versioned Store |
| i18n | English literals; `Intl` only for numbers/dates | Catalog + locale preference; fallback tests |
| Shell | Thinner `main.ts` after v0.1.8 | New UI must live in the extracted views/controllers, not return to the composition root |

The following choices are final for implementation; changing one requires a
plan update before code changes:

- Favorites support Markdown and standalone Mermaid previews, not images or
  Settings. They live in session v2, newest first, unique by canonical path,
  capped at 50.
- Both `documentVisitHistory` (50) and `closedTabsHistory` (20) persist. Missing
  paths are retained and checked lazily on use; a failed open offers removal.
- Annotations use a separate `markmaid-annotations.json` app Store with its own
  `version: 1`. They are not embedded in `markmaid-state.json` and never live
  beside a source document.
- v0.1.9 highlight creation is **Find-based**: the user highlights the current
  Find match, whose UTF-16 source offsets are already known. Arbitrary DOM text
  selection is deferred because rendered Markdown does not provide a reliable
  character-for-character source mapping.
- Locale preference values are exactly `"system" | "en" | "zh-Hans"`.
  Frontend code resolves `system` from `navigator.languages` and sends the
  resolved `"en" | "zh-Hans"` locale to Rust when rebuilding native menus.

Release/development prerequisite:

- v0.1.8 must ship a forward-schema protection before any v0.1.9 build is run
  against a real user Store: a recognized-but-unsupported session version must
  disable session writes for that process. Until that protection is in the
  published v0.1.8 build, v0.1.9 manual work uses only an isolated app-data
  profile or disposable Store copy. A backup alone is not a substitute for the
  automated no-overwrite test.

## 5. Contracts to establish before implementation

### 5.1 Favorites contract

```text
FavoriteEntry {
  path: canonical absolute path string
  kind: "document" | "mermaid"
  addedAt: number  // epoch ms
}

FavoritesState {
  entries: FavoriteEntry[]  // newest first, unique by path, cap 50
}
```

Rules:

- Favoriting never creates, renames, or writes workspace files.
- Only ready Markdown and standalone Mermaid tabs may be favorited. Images,
  loading/error tabs, and Settings are never eligible.
- Missing files remain listed. After a failed open the actionable notice offers
  Remove; metadata changes only if the user confirms that action.
- `toggleFavorite` removes an existing entry or inserts a new entry at index 0;
  re-adding a previously removed path gives it a new `addedAt` and newest rank.
- Normalization keeps the valid duplicate with the greatest `addedAt`, sorts by
  `addedAt` descending, and preserves first-input order for equal timestamps
  before applying the cap. Timestamps are finite non-negative integers.
- Favorites are independent of Recents: opening a favorite updates Recents
  through the existing open path.

Quick Open:

- Extend `QuickSwitcherItem.kind` with `"favorite"`. Ordering and dedupe are
  deterministic: open tabs → favorites → workspace query matches → recents;
  the first source wins for duplicate paths. Empty queries show tabs,
  favorites, and recents; workspace results remain query-driven.
- Query matching uses the same path/name rules as other Quick Open sources.
- Activating a favorite opens or focuses the preview through existing open
  paths.

Command Palette:

- `toggleFavorite` enabled when the active tab is a favoritable document.
- Add static IDs `file.toggle-favorite` and `file.open-favorites`. The latter
  opens Quick Open with `scope: "favorites"`; the same builder, renderer,
  keyboard handling, and activation path are reused. Clearing the scope returns
  to `"all"`; no second picker or ranking implementation is allowed.
- Favorites scope is never invisible: Quick Open shows a localized scope chip
  with a keyboard-accessible clear action. Clicking it, or pressing
  Backspace/Delete with an empty query, returns to `"all"`. Closing the overlay
  discards the scope, and ordinary `Cmd+P` always opens in `"all"`.
- `file.open-favorites` is disabled with a localized reason when the list is
  empty.
- Labels/keywords localized in v0.1.9 catalogs.

### 5.2 Bookmarks / highlights / notes (sidecar) contract

Store annotations in the dedicated app Store `markmaid-annotations.json` under
key `annotations`. **Never** write into the source Markdown file.

```text
AnnotationDocKey = canonical path

Bookmark {
  id: opaque string
  path
  title: user or derived heading string (max 120 UTF-16 code units)
  scrollTop: number
  fragment?: heading anchor
  createdAt / updatedAt
}

Highlight {
  id
  path
  start: number       // zero-based UTF-16 source offset
  end: number         // exclusive UTF-16 source offset
  quote: string       // exact selected Find text, max 512 code units
  prefix / suffix     // up to 64 source code units each
  sourceHash: string  // SHA-256 hex of Markdown source at creation/re-anchor
  colorToken: "yellow" | "green" | "blue" | "pink"
  createdAt / updatedAt
}

Note {
  id
  path
  body: plain text, max 4,096 UTF-16 code units
  bookmarkId?: optional link
  createdAt / updatedAt
}

AnnotationsByPath {
  bookmarks: Bookmark[]
  highlights: Highlight[]
  notes: Note[]
}

AnnotationStoreV1 {
  version: 1
  documents: Record<canonicalPath, AnnotationsByPath>
}
```

Rules:

- IDs are `crypto.randomUUID()` values. UUID uniqueness is global across all
  paths and annotation kinds; normalization walks document buckets in stored
  key order and arrays in stored order, dropping every duplicate after the
  first valid record. New records are inserted newest-first; editing does not
  silently reorder them.
- A record's `path` must exactly match its normalized document-bucket key.
  Rename rewrites both. A target bucket that already contains metadata is a
  preflight conflict, not an implicit merge or overwrite; the user must manage
  the stale target metadata before retrying.
- Open the Store with `{ autoSave: 150 }`. A Store open/parse failure starts
  with an empty in-memory annotation model, disables annotation mutations for
  that process, and shows one privacy-safe notice; it must not overwrite the
  unreadable file. Favorites/session persistence remains available. A valid
  Store containing individual corrupt buckets stays writable after those
  buckets are isolated by normalization.
- Caps are fixed: 50 bookmarks per path / 500 global; 50 highlights per path /
  500 global; 50 notes per path / 500 global. Serialized Store payload is
  capped at 1 MiB. A mutation that would exceed a count/body/store cap is
  rejected with an actionable notice; existing data is never silently
  truncated.
- If an otherwise valid loaded Store already exceeds a count or 1 MiB cap, keep
  the complete normalized model visible but enter annotation recovery-only
  mode. Do not rewrite or truncate it. The UI permits only explicit deletion;
  when a deletion candidate brings the complete model within bounds, persist
  that candidate and then resume ordinary mutations.
- The 1 MiB limit is the UTF-8 byte length of
  `JSON.stringify({ annotations: normalizedStore })`, measured with
  `TextEncoder`, and is checked on an immutable candidate before changing live
  state. Store writes are serialized: a write in flight is followed by at most
  one write of the newest dirty snapshot. Failure disables later writes and
  shows one safe notice; it never produces an unhandled rejection.
- User text limits are measured in UTF-16 code units but truncation, where
  explicitly offered by the UI, must not split a surrogate pair. Bookmark
  titles and note bodies are rejected when empty after trimming; stored text
  preserves user content and normalizes CRLF/CR to LF. Highlight quote/context
  are derived from source and are never user-truncated.
- `createdAt`/`updatedAt` values are finite non-negative integer epoch
  milliseconds and `updatedAt >= createdAt`. A note's `bookmarkId`, when
  present, must refer to a bookmark in the same path bucket. Load clears a
  dangling link without dropping the note; deleting a bookmark retains linked
  notes as path notes and clears their links.
- `annotations.highlight-find-match` is enabled for a ready Markdown tab. It
  opens the existing Document Find overlay in `mode: "highlight"`; the Add
  Highlight action remains disabled until a current match exists, and explicit
  confirmation persists that match's offsets, quote/context, and SHA-256.
  Mermaid/image tabs cannot be highlighted in v0.1.9.
- `quote` is `source.slice(start, end)` with original casing, never the user's
  potentially case-different Find query. `sourceHash` is SHA-256 of
  `TextEncoder().encode(readyTab.source)` with no newline or Unicode
  normalization.
- On open/reload, matching `sourceHash` + `quote` at the stored offsets is
  active. Otherwise search `prefix + quote + suffix`; exactly one match
  re-anchors and updates app metadata, while zero/multiple matches mark the
  highlight stale. Never guess between multiple matches.
- Compute the current source hash once per loaded document revision, not once
  per highlight. Re-anchor at most the per-path cap (50), yield between records,
  and guard the run with the existing generation/cancellation pattern so a tab
  switch, reload, or close cannot apply stale results. Commit all successful
  re-anchors for one document as one immutable annotation mutation and one
  scheduled Store write, not 50 writes.
- Rendering highlights in preview must be overlay/CSS decoration only, not an
  `tab.html` mutation. HTML/PDF export always ignores annotations in v0.1.9.
- Notes are private app data; Copy Diagnostics must not include note bodies or
  paths.
- Static Command Palette IDs are `annotations.add-bookmark`,
  `annotations.show-bookmarks`, `annotations.highlight-find-match`,
  `annotations.add-note`, and `annotations.manage`. Bookmark/note/highlight rows
  live in one annotation overlay; dynamic IDs and paths never enter
  `CommandId`.
- Bookmark creation captures current `scrollTop` and the nearest preceding
  heading `id` when one exists. Jump prefers the fragment and falls back to
  `scrollTop`.
- The annotation overlay uses `role="dialog"`, traps Tab/Shift+Tab, closes and
  restores focus on Escape, moves list selection with Arrow keys/Home/End, and
  activates with Enter. Delete requires a confirmation inside the same dialog;
  every icon-only action has a localized accessible name and result changes use
  the existing live-region announcement path.
- The tab context menu reuses its existing roving-keyboard/focus-restore
  behavior for Toggle Favorite; the new action must be reachable without a
  pointer.
- Workspace rename rewrites favorite/history/closed-tab paths and annotation
  document keys after native success. Workspace Trash confirmation explicitly
  warns when app-local metadata exists, then removes metadata under the trashed
  prefix after native success. External deletion retains metadata until the
  user removes it.
- Before a workspace rename, compute session and annotation rewrites without
  mutating live state. Block the native rename when a target annotation bucket
  conflicts or the rewritten annotation payload would exceed a cap. After a
  native rename/Trash succeeds, apply in-memory metadata updates and schedule
  the two Stores independently; there is no false cross-Store atomicity. If a
  Store write then fails, do not roll back the filesystem operation—retain the
  in-memory result, disable that Store, and show which app metadata was not
  saved. A disabled annotation Store must not silently discard metadata during
  rename/Trash; confirmation lets the user cancel or explicitly continue with
  stale app metadata.

Privacy:

- Paths are stored because the product already persists paths for tabs/recents.
- Note bodies and highlight excerpts stay local; no upload; exclude from
  Copy Details / Copy Diagnostics allowlists.

### 5.3 Persisted reading history contract

Today per-tab `scrollTop` already survives restart. Session v2 additionally
persists the existing runtime shapes and limits. The record/move reducers stay
authoritative, but activation must change where current behavior consumes a
closed entry before an asynchronous open result is known:

```text
DocumentNavigationEntry { path, scrollTop, fragment? }
// Bounded list + index for Back/Forward

ClosedTab { kind, path, scrollTop, index }
```

Rules:

- Enforce the existing 50-entry visit cap and 20-entry closed-tab cap in both
  reducers and session normalization.
- Restore without filesystem I/O. On Back/Forward/Reopen, the existing preview
  path performs the check; an unavailable target remains in history until the
  user chooses Remove, then index reconciliation is persisted.
- Back/Forward may move the index to an unavailable entry so Retry/Remove has a
  stable target. Reopen peeks rather than pops; it consumes the closed entry
  only after a ready preview is established. Failure leaves the entry in
  closed history and must not create duplicate error tabs on repeated retries.
- Removing a visit entry selects the nearest surviving entry (previous first,
  otherwise next) and clamps the index; removing a closed entry removes exactly
  that occurrence. These are explicit tested reducers, not view-only filtering.
- Focus Mode remains runtime-only and is not persisted.
- Migration fills empty histories and index `-1` for v1 sessions.

### 5.4 Localization contract

```text
UiLocalePreference = "system" | "en" | "zh-Hans"
```

Rules:

- Extract user-visible strings from shell / commands / overlays into a catalog
  at `src/i18n/messages.ts`. English is the complete key authority; the
  Simplified Chinese catalog is typed as the same key set.
- `src/i18n/index.ts` exposes `resolveUiLocale(preference, languages)` and
  `createTranslator(locale)`. `system` chooses `zh-Hans` for `zh`, `zh-Hans`,
  `zh-CN`, or `zh-SG`; `zh-Hant`, `zh-TW`, `zh-HK`, and `zh-MO` do not silently
  convert to Simplified Chinese and resolution continues to the next preferred
  language before falling back to `en`.
- Resolution respects preferred-language order: iterate `languages`; return
  `zh-Hans` for the first Simplified-Chinese match, return `en` for the first
  English match, skip unsupported languages (including Traditional Chinese),
  and fall back to `en` only after exhaustion. Thus `en-US, zh-CN` resolves to
  English, while `zh-Hant, zh-CN` resolves to Simplified Chinese.
- English defines `MessageKey`; the production Chinese catalog must satisfy
  `Record<MessageKey, string>` at compile time. The resolver accepts
  a partial catalog and falls back per key to English; unit tests use a sparse
  test catalog to exercise that path.
- Translators return plain text. They never HTML-escape interpolation values;
  escaping belongs to the concrete sink (`textContent`, HTML text, attribute,
  or URL) so strings are neither under-escaped nor double-escaped. Catalog
  interpolation rejects missing/unknown placeholders in tests.
- Add generated IPC command `set_ui_locale({ locale: "en" | "zh-Hans" })` and
  Rust `UiLocaleState`. `build_menu` reads that state; bootstrap and preference
  changes call the command and rebuild the menu while preserving Recents and
  Reopen availability. All MarkMaid-authored menu/submenu labels are localized;
  macOS standard role items (About, Services, Hide, Quit, Undo/Redo,
  Cut/Copy/Paste, Full Screen, Window roles) remain supplied by Tauri/macOS.
  Those standard items follow the macOS system language and may intentionally
  differ from MarkMaid's selected UI locale.
- Do not localize document contents, code fences, or user note bodies.
- `COMMAND_CATALOG_METADATA` becomes a locale-derived factory. Labels,
  sections, disabled reasons, and primary keywords localize; English keywords
  remain appended in Chinese for muscle memory and deterministic search.
- Persist `uiLocale` in session v2. Changing it rebuilds shell/native menu and
  command catalogs but must keep the current preview DOM node attached, retain
  scroll/focus, and avoid reloading Markdown.
- While preference is `system`, handle `window.languagechange` by resolving the
  new language list and applying the same DOM-preserving shell/menu update;
  keep the persisted preference as `system`. Explicit `en`/`zh-Hans` ignores
  that event. App-authored dates/counts use `Intl` with the resolved locale.

### 5.5 Session schema bump

Using the v0.1.8 migrator:

- `migrateV1ToV2` adds `favorites: []`, `uiLocale: "system"`,
  `documentVisitHistory: []`, `documentVisitHistoryIndex: -1`, and
  `closedTabsHistory: []`. Annotations are not part of the session schema.
- Round-trip fixtures for v1→v2 and native v2.
- Migration returns a discriminated outcome: `ready(current)`, `invalid`, or
  `unsupported(version)`. Invalid/missing/non-object data starts from defaults
  and remains writable under the existing recovery policy; a well-formed
  integer version other than 1 or 2 is `unsupported`, starts from defaults with
  one privacy-safe notice, and disables session writes so downgrade/future data
  cannot be overwritten. Invalid annotation Store values normalize
  independently; one corrupt document bucket is dropped without discarding
  valid buckets.

## 6. Implementation sequence

1. **Foundation gate:** first ship v0.1.8 with session write-failure handling and
   unsupported-future-schema no-overwrite protection; then rebase, verify
   generated IPC, v1 migrator, extracted views, and `CI=true pnpm check` before
   feature work. Use only isolated/disposable Store data until this gate passes.
2. **Version identity:** immediately after the clean v0.1.8 baseline, run
   `pnpm release:prepare -- 0.1.9` and commit the synchronized version metadata
   before any code can write session v2. Development builds that create v2 data
   must identify themselves as 0.1.9.
3. **Session v2:** add schema/migration fixtures, then persist the already
   bounded histories and locale/favorites defaults.
4. **Favorites slice:** reducers → tab context action → Quick Open kind/scope →
   two static palette commands; include rename/trash path rewriting.
5. **Annotation Store slice:** schema/caps/load-save failure boundary, then
   bookmarks and notes through the shared overlay.
6. **Highlight slice:** Find-match capture, SHA-256/context anchoring,
   re-anchor/stale states, preview-only decoration, and export exclusion test.
7. **Localization slice:** typed catalogs, shell/palette/settings coverage,
   locale switch without preview replacement, then generated
   `set_ui_locale` native-menu synchronization.
8. **Release integration:** update README/changelog/roadmap/release notes and run
   the full automated/manual matrix; re-check, but do not repeat, the already
   committed 0.1.9 version synchronization.

Each slice is one or more focused commits and must leave `CI=true pnpm check`
green. Do not start a later slice with a knowingly failing gate.

## 7. Testing and QA

### Automated

- Migration fixtures: minimal/full v1→v2, full v2 round-trip, invalid v2 fields,
  favorite cap/order/dedupe, both history bounds/index reconciliation, and
  unsupported future-version no-overwrite behavior.
- Quick Open tests for exact tab → favorite → workspace → recent order,
  cross-source dedupe, empty/query behavior, and favorites-only scope.
- Command availability tests for toggle favorite / annotation commands.
- Annotation tests for caps/1 MiB rejection, corrupt-bucket isolation,
  bookmark fragment fallback, exact/re-anchored/stale highlights, and
  rename/trash/external-missing behavior.
- Structural performance tests use the existing large-document fixture with 50
  highlights and assert one hash per revision, at most 50 re-anchor attempts,
  yielding/cancellation, stale-generation rejection, and one batched mutation;
  they add no wall-clock CI threshold.
- Persistence tests for serialized annotation writes, dirty-during-write
  coalescing, write failure, preflight rename collision/size rejection, and
  independent session/annotation Store failure.
- i18n tests for complete key parity, missing-key English fallback, system
  resolution, interpolation escaping boundary, preference round-trip, and
  preview DOM identity across locale changes.
- Privacy tests: diagnostics / Copy Details exclude note bodies and full paths
  as per existing allowlists.
- Export tests prove annotation marks/note bodies never enter HTML/PDF payloads.
- Full gate: `CI=true pnpm check`.

### Manual

- Favorite a file, quit, relaunch; unfavorite; favorite missing file behavior.
- Add bookmark/note and highlight a Find result; confirm source SHA-256 is
  unchanged before/after every operation.
- Exercise exact, uniquely re-anchored, ambiguous, and stale highlight states
  after external edit + Reload.
- Switch UI to Chinese; smoke Command Palette, Settings, empty states; switch
  back to English / System.
- VoiceOver labels still present for new controls.

## 9. Risks and mitigations

| Risk | Mitigation |
| --- | --- |
| Highlight offsets break after edits | SHA-256 of the exact UTF-8 encoding of the in-memory source string + exact quote/context re-anchor; ambiguous or absent matches become stale |
| Newer session is opened by an older build | Ship unsupported-version write protection in v0.1.8 before v0.1.9 development touches real Store data |
| Filesystem mutation succeeds but one metadata Store fails | Preflight conflicts/caps, independent serialized writes, explicit partial-save notice, and no false rollback claim |
| Highlight recovery blocks a large document | Hash once per revision, cap at 50, yield/cancel between records, batch one mutation, and keep structural performance smoke in the normal gate |
| Annotation Store grows large | Fixed count/body caps plus 1 MiB serialized mutation guard; never store document bodies |
| i18n half-coverage looks broken | Typed production-catalog key parity plus a manual inventory of shell, views, notices, empty/error states, Settings, palette, and authored native menu labels |
| Palette overloaded with dynamic items | Static commands + small pickers; paths never become CommandIds |
| Scope creep into Workspace Switcher / search | Explicit out of scope; refuse partial search indexes |
